# RTOS-总览

## 原始问题

为什么嵌入式知识库里需要单独建立 `RTOS` 目录？它和 `外设`、`通信协议`、`项目与架构` 的区别是什么？

## 先给结论

`RTOS` 目录用于沉淀实时系统的任务组织方式，服务的是“把多个功能稳定并发地跑起来”这条主线。

优先放到这里的内容通常包括：

1. 任务调度、优先级、任务切换、栈和上下文。
2. 信号量、互斥锁、消息队列、事件组、软件定时器。
3. 中断与任务配合、临界区、实时性和优先级反转。
4. FreeRTOS 或其他 RTOS 的核心机制与工程落地。

不优先放到这里的内容通常包括：

1. 单一外设本身的原理和用法，优先放 `外设`。
2. 具体协议帧格式和通信细节，优先放 `通信协议`。
3. 更抽象的系统架构和模块设计，优先放 `项目与架构`。

## 这个目录解决什么问题

1. 单个功能能跑，但多个功能一起跑就乱。
2. 不清楚任务、队列、中断和定时器应该怎么组合。
3. 工作里需要从“裸循环逻辑”升级到“实时系统组织”。

## 后续可扩展主题

1. `RTOS-任务调度基础`
2. `RTOS-任务间通信`
3. `RTOS-互斥锁与优先级反转`
4. `RTOS-中断与任务协作`
5. `RTOS-软件定时器`
6. `RTOS-内存管理`

## 关键要点

1. RTOS 的核心不是 API 数量，而是系统如何稳定组织并发行为。
2. 后续凡是更偏任务调度、同步和实时性的问题，优先归到这里。
3. 这部分能力是 MCU 工作从“会写功能”走向“能维护系统”的关键一步。
