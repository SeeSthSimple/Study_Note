# C_C++-总览

## 原始问题

为什么嵌入式知识库里要单独保留 `C_C++` 目录？后续哪些内容应该放这里，它在嵌入式工作里主要解决什么问题？

## 先给结论

`C_C++` 目录用于沉淀语言、内存、对象模型、资源管理和调试基础，服务的是“写得出来、看得懂、改得动、查得准”这条主线。

优先放到这里的主题通常包括：

1. C 语言基础、指针、数组、字符串、结构体、位操作。
2. 动态内存、栈和堆、内存布局、内存错误和调试工具。
3. C++ 对象生命周期、RAII、拷贝控制、移动语义、异常安全、智能指针。
4. 面向嵌入式常见的接口设计、资源管理和代码可维护性问题。

不优先放到这里的内容通常包括：

1. 更偏硬件本质的寄存器、电平、时钟和复位，优先放 `硬件`。
2. 更偏外设本身的 GPIO、UART、I2C、SPI，优先放 `外设`。
3. 更偏 Linux 驱动和内核接口的内容，优先放 `Linux` 或 `驱动开发`。

## 这个目录解决什么问题

它主要解决下面几类现实问题：

1. 能看懂代码但写不稳，改动时容易引入内存和生命周期问题。
2. 驱动、协议、RTOS、应用层都要写 C 或 C++，但语言基础不足会让上层主题处处卡住。
3. 面试和工作中经常要解释指针、内存、资源管理和异常安全，这些不能混在其他主题里零散处理。

## 关键要点

1. 这个目录承接的是语言与内存基础，不是外设或系统框架本身。
2. 语言基础不稳，会直接放大驱动、协议、RTOS 和项目维护成本。
3. 后续所有和内存、对象、资源管理强相关的笔记，优先归到这里。
