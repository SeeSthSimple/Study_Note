# C语言-指针与数组

## 原始问题

为什么 C 里指针和数组总是被一起讲，但一到真实代码里又老是混淆？什么时候它们像，什么时候它们根本不是一回事？为什么很多越界和崩溃都跟这两个概念有关？

## 先给结论

指针和数组的关系可以先抓住这几个最重要的结论：

1. 数组是一整块连续对象，指针是保存地址的变量，它们不是同一个东西。
2. 数组名在很多表达式里会退化成首元素指针，但 `sizeof(array)`、可修改性和对象语义并不会一起退化。
3. 指针算术不是按字节盲目移动，而是按“指向类型的大小”移动。
4. 指针最危险的地方不是语法，而是地址是否有效、生命周期是否还在、边界是否还合法。
5. 写工程代码时，任何“指针 + 长度”都必须成对出现，否则后续几乎一定会出边界问题。

如果只能背“数组名就是指针”，但讲不清数组退化、`sizeof`、一过尾地址和函数参数语义，就还没有真正掌握这个主题。

## 这个知识解决什么问题

这篇笔记主要解决下面几类问题：

1. 会写 `int *p` 和 `int a[10]`，但一到函数传参和 `sizeof` 就开始判断错。
2. 越界、悬空、段错误常常发生，但不知道根因是“地址无效”还是“边界错了”。
3. 读驱动、协议、Linux 或库代码时，经常被缓冲区遍历、回调参数、数据拷贝卡住。
4. 面试时知道“数组和指针不完全相同”，却讲不出最关键的区别。

它在 AI 时代依然重要，因为 AI 生成的 C 代码最容易在“指针看起来对、边界其实错”这种地方埋雷。你越理解数组和指针的真实语义，就越能筛掉那些能编译、却不可靠的代码。

## 核心概念 / 本质机制

### 1. 数组是什么

数组是一个完整对象，特点是：

1. 元素类型固定。
2. 元素个数固定。
3. 内存连续。
4. 数组名代表这整块对象。

### 2. 指针是什么

指针是一个变量，它保存某个地址，并且带有“这个地址应被当成什么类型解释”的信息。

例如：

```c
int arr[4] = {1, 2, 3, 4};
int *p = arr;
```

这里 `arr` 是数组对象，`p` 是单独的指针变量。

### 3. 为什么经常说“数组会退化成指针”

因为在很多表达式里，数组名会自动转换成指向首元素的指针。

例如：

```c
arr[2]
*(arr + 2)
```

这两种写法等价，但不代表数组和指针完全相同。最关键的区别之一是：

1. `sizeof(arr)` 得到整个数组大小。
2. `sizeof(p)` 得到指针变量大小。

### 4. 指针算术为什么容易出错

`p + 1` 的含义不是地址加 1 字节，而是跳过一个当前类型对象。

所以：

1. `int *p` 的 `p + 1` 会跳过一个 `int`
2. `char *p` 的 `p + 1` 才是跳过一个字节

### 5. 一过尾地址是什么

C 允许得到“数组最后一个元素后面一个位置”的地址，但不能对它解引用。

```c
int *end = arr + 4;
```

这里 `end` 可用于比较和循环终止，但 `*end` 是未定义行为。

### 6. 为什么函数参数里的数组会“丢长度”

因为函数参数里的数组写法本质上仍然退化成指针：

```c
void print_array(int arr[], size_t size);
```

它和：

```c
void print_array(int *arr, size_t size);
```

本质一致，所以长度必须单独传入。

## 数据流 / 控制流 / 时序关系

这个主题最典型的数据流通常是：

```text
调用者定义数组
-> 数组名退化成首元素地址
-> 地址和长度一起传给函数
-> 函数按边界遍历或修改数据
-> 调用者继续使用原数组
```

最容易出问题的地方有三类：

1. 只传指针，不传长度。
2. 传了长度，但长度和真实数组不一致。
3. 指针已经失效，函数还继续访问。

## 最小可运行示例

```c
#include <stdio.h>
#include <stddef.h>

static void fill(int *data, size_t size, int base)
{
    size_t i;

    if (data == NULL) {
        return;
    }

    for (i = 0; i < size; ++i) {
        data[i] = base + (int)i;
    }
}

static void print_array(const int *data, size_t size)
{
    size_t i;

    if (data == NULL) {
        return;
    }

    for (i = 0; i < size; ++i) {
        printf("%d ", data[i]);
    }
    printf("\n");
}

int main(void)
{
    int arr[4] = {0};
    int *p = arr;

    fill(arr, sizeof(arr) / sizeof(arr[0]), 10);

    printf("sizeof(arr) = %zu\n", sizeof(arr));
    printf("sizeof(p) = %zu\n", sizeof(p));
    printf("arr[2] = %d\n", arr[2]);
    printf("*(p + 2) = %d\n", *(p + 2));

    print_array(arr, sizeof(arr) / sizeof(arr[0]));
    return 0;
}
```

预期输出类似：

```text
sizeof(arr) = 16
sizeof(p) = 8
arr[2] = 12
*(p + 2) = 12
10 11 12 13
```

## 代码解读

### 1. 为什么 `int *p = arr;` 合法

因为 `arr` 在这个表达式里退化成 `&arr[0]`，所以可以赋给 `int *`。

### 2. 为什么 `sizeof(arr)` 和 `sizeof(p)` 不一样

`arr` 是整个数组对象，所以得到整个数组占用字节数；`p` 是指针变量，所以得到的是指针本身大小。

### 3. 为什么函数一定要带 `size`

因为 `fill` 和 `print_array` 拿到的只是首地址，不知道数组里有多少元素。如果不额外传长度，函数没有可靠办法知道边界。

### 4. 为什么 `const int *data` 很重要

它能明确表达“这个函数只读不改”，让接口意图更清晰，也更容易防止误改数据。

## 正确写法 vs 常见错误写法

| 场景 | 正确写法 | 常见错误写法 | 为什么错 |
| --- | --- | --- | --- |
| 传数组给函数 | 传 `指针 + 长度` | 只传 `int *` 不传长度 | 被调方不知道边界 |
| 计算元素个数 | `sizeof(arr) / sizeof(arr[0])` 仅在数组本作用域使用 | 在函数参数里也这么算 | 参数里已经退化成指针 |
| 一过尾地址 | `for (p = arr; p < arr + n; ++p)` | 对 `arr + n` 解引用 | 一过尾地址不能访问 |
| 指针有效性 | 只访问仍然存活的对象 | 返回局部变量地址 | 函数返回后地址失效 |
| 修改数据 | 需要写时用 `int *` | 只读接口却暴露可写指针 | 容易误改调用方数据 |

## 边界条件与适用范围

1. 指针算术只应在同一个数组对象范围内进行。
2. 允许计算一过尾地址，但不能解引用。
3. 不同平台下指针大小可能不同，不能假设一定是 4 字节或 8 字节。
4. 多维数组、`char *`、`void *`、函数指针是更进一步的话题，不能用一套直觉全部混着理解。

## 常见坑与排查

| 现象 | 常见根因 | 优先验证方法 |
| --- | --- | --- |
| 数组长度算错 | 在函数参数里对指针使用 `sizeof` | 看变量声明位置和实际类型 |
| 段错误 | 指针为空、悬空或越界 | 看地址来源和生命周期 |
| 数据被改乱 | 本应只读的接口暴露了可写指针 | 检查 `const` 设计 |
| 偶发错误 | 循环终止条件写错，越过边界 | 打印下标范围，配合 sanitizer |

## 工程落地建议

### 1. 任何缓冲区接口默认都带长度

推荐风格：

1. `const uint8_t *data, size_t len`
2. `char *buf, size_t buf_size`
3. `int *out_value, size_t out_count`

### 2. 区分“借用”和“拥有”

很多 C 接口里的指针只是借用，不负责释放。工程里一定要在接口注释或命名里写清楚“谁拥有这块内存”。

### 3. 优先把遍历写成边界明确的形式

推荐：

```c
for (i = 0; i < size; ++i) { ... }
```

或者：

```c
for (p = begin; p < end; ++p) { ... }
```

## 性能、稳定性、可维护性影响

1. 指针和数组理解不稳，会直接放大越界、悬空和接口误用问题。
2. 明确的边界设计比“省一个参数”更重要，因为绝大多数缓冲区 bug 都不是算法复杂，而是边界失控。
3. `const`、长度参数和清晰的数据拥有关系，能显著提升可维护性。

## 面试 / 问答怎么讲

### 30 秒版本

数组和指针关系很近，但不是一回事。数组是完整连续对象，指针是保存地址的变量。数组名在很多表达式里会退化成首元素指针，所以它们常被一起使用；但 `sizeof`、可修改性和对象语义都不同。工程里最关键的是任何缓冲区接口都要把“指针和长度”一起传。

### 3 分钟版本

可以先举 `int arr[4]` 和 `int *p = arr` 的例子，说明访问元素时写法看起来相近，但 `sizeof(arr)` 得到的是整个数组大小，`sizeof(p)` 得到的是指针大小。再补充函数参数里的数组本质也是指针，所以长度必须单独传入。最后强调一过尾地址、悬空指针和越界访问这些工程风险。

### 10 分钟版本

可以再结合一个缓冲区处理函数展开：调用方定义数组，把首地址和长度传给函数，函数按边界遍历或修改。然后说明哪些错误会把这条链打断，比如在函数里用 `sizeof` 算长度、返回局部变量地址、对一过尾地址解引用。再补充如何用 sanitizer 和调试器验证边界错误。

3. 写一个故意对 `arr + n` 解引用的小例子，用 sanitizer 看报错。
4. 把自己现有一段“只传指针不传长度”的代码改成显式长度接口。

## 关键要点

1. 数组是对象，指针是变量，它们不是同一个概念。
2. 数组名常退化成首元素指针，但 `sizeof` 和对象语义不会一起退化。
3. 指针算术按类型大小移动，不是按字节盲目移动。
4. 一过尾地址可以比较，不能解引用。
5. 工程里缓冲区接口必须把“指针 + 长度”成对传递。
