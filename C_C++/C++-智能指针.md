# C++-智能指针

## 原始问题

C++ 为什么推荐智能指针？`unique_ptr`、`shared_ptr`、`weak_ptr` 到底分别解决什么问题？什么时候该用，什么时候不该用？

## 先给结论

智能指针的核心价值，不是“自动帮你 delete”，而是把所有权语义写进类型系统：

1. `std::unique_ptr` 表达独占所有权，默认优先。
2. `std::shared_ptr` 表达共享所有权，只在确实需要共享生命周期时使用。
3. `std::weak_ptr` 表达观察但不拥有，主要用来打破共享引用环或做安全观察。
4. 裸指针在现代 C++ 里更适合表达“借用”或“非拥有观察”，不适合作为默认资源拥有者。

如果只会背智能指针名字，但讲不清所有权、引用计数、循环引用和 `weak_ptr::lock()` 的意义，就还没有真正掌握智能指针。

## 这个知识解决什么问题

这篇笔记主要解决下面几类问题：

1. 从手写 `new/delete` 过渡到现代 C++ 时，不知道智能指针到底替代了什么。
2. 不清楚 `unique_ptr` 和 `shared_ptr` 的真实差别，导致默认乱用共享所有权。
3. 知道 `weak_ptr` 这个名字，但不知道它为什么存在。
4. 写类之间的关系时，经常把所有权设计搞混，最终造成泄漏、双重释放或复杂耦合。

它在 AI 时代依然重要，因为 AI 很容易生成能编译的智能指针代码，但经常会错误选择所有权模型，比如默认上 `shared_ptr`，或者在存在循环引用的关系里不引入 `weak_ptr`。理解智能指针，才能判断“自动管理”背后的资源设计是否真的合理。

## 核心概念 / 本质机制

### 1. 智能指针不是普通指针替身，而是所有权工具

看到智能指针时，优先问的不是“它像不像裸指针”，而是：

1. 谁拥有对象。
2. 对象生命周期由谁决定。
3. 是否允许多个地方共同延长生命周期。
4. 是否只需要观察，不需要拥有。

智能指针的本质，是把这些语义放到类型层面表达出来。

### 2. `std::unique_ptr` 的本质

`unique_ptr` 表示：

1. 一块资源同一时刻只能有一个明确 owner。
2. owner 销毁时，资源自动释放。
3. 默认不能拷贝，只能移动。

它最适合：

1. 工厂函数返回动态对象。
2. 类独占拥有某个堆对象。
3. 需要明确资源归属，不想共享生命周期。

### 3. `std::shared_ptr` 的本质

`shared_ptr` 表示：

1. 多个对象共同拥有同一资源。
2. 资源何时释放，由引用计数是否归零决定。
3. 任何一个 `shared_ptr` 都可以延长对象生命周期。

它适合：

1. 确实存在共享生命周期需求。
2. 资源不知道最终会由哪个消费者先结束。

但它也带来代价：

1. 引用计数开销。
2. 所有权边界更难推理。
3. 循环引用会导致泄漏。

### 4. `std::weak_ptr` 为什么存在

`weak_ptr` 不拥有对象，它的作用是：

1. 观察 `shared_ptr` 管理的对象。
2. 不增加引用计数。
3. 在需要访问时通过 `lock()` 尝试获取临时 `shared_ptr`。

它最重要的用途是：

1. 打破 `shared_ptr` 环。
2. 表达“我知道这个对象可能存在，但我不负责延长它寿命”。

### 5. 为什么默认优先 `unique_ptr`

因为大多数资源关系其实不是共享，而是明确归属：

1. 一个对象只属于一个管理者。
2. 生命周期边界清楚。
3. 不需要引用计数。
4. 代码更容易推理。

默认上 `shared_ptr` 的常见后果是：

1. 所有人都能延长对象寿命。
2. 谁该释放边界越来越模糊。
3. 系统越来越像“谁都能持有，谁也说不清什么时候结束”。

### 6. 自定义 deleter 为什么重要

智能指针不只管 `delete`，还可以管理非标准释放逻辑，比如：

1. `free()` 释放的 C 接口返回内存。
2. `fclose()` 关闭文件。
3. `close()` 释放 fd。
4. 第三方库自带的 destroy 函数。

这让智能指针可以把更多 C 风格资源纳入 RAII 范围。

## 数据流 / 控制流 / 时序关系

智能指针的主线可以理解成：

```text
创建资源
-> 选择正确所有权类型
-> 在业务逻辑中传递拥有者或观察者
-> 作用域结束或引用计数归零
-> 自动释放资源
```

关键区别在于：

1. `unique_ptr` 的生命周期由唯一 owner 决定。
2. `shared_ptr` 的生命周期由最后一个共享 owner 决定。
3. `weak_ptr` 不影响生命周期，只参与观察。

很多 bug 不是“智能指针失效”，而是所有权类型从一开始就选错了。

## 最小可运行示例

下面给一个同时展示 `unique_ptr`、`shared_ptr`、`weak_ptr` 的最小示例。

```cpp
#include <iostream>
#include <memory>

struct Node {
    explicit Node(int v) : value(v) {
        std::cout << "Node " << value << " created\n";
    }

    ~Node() {
        std::cout << "Node " << value << " destroyed\n";
    }

    int value;
    std::weak_ptr<Node> next;
};

int main()
{
    auto owner = std::make_unique<int>(42);
    std::cout << "unique value = " << *owner << '\n';

    auto a = std::make_shared<Node>(1);
    auto b = std::make_shared<Node>(2);
    a->next = b;
    b->next = a;

    if (auto locked = a->next.lock()) {
        std::cout << "a->next = " << locked->value << '\n';
    }

    return 0;
}
```

编译和运行：

```bash
g++ -Wall -Wextra -Werror -std=c++17 demo.cpp -o demo
./demo
```

预期现象：

1. `unique_ptr` 管理的整数在 `main` 结束时自动释放。
2. 两个 `Node` 也会正常析构，因为 `next` 用的是 `weak_ptr`，没有形成共享引用环。

## 代码解读

### 1. 为什么 `std::make_unique<int>(42)` 比 `new int(42)` 更推荐

因为它直接返回带所有权语义的对象，不需要你额外记得写 `delete`。

### 2. 为什么 `Node::next` 用 `weak_ptr`

如果这里用 `shared_ptr`：

1. `a` 持有 `b`。
2. `b` 也持有 `a`。
3. 两边引用计数都不会归零。
4. 结果就是泄漏。

### 3. 为什么访问 `weak_ptr` 要先 `lock()`

因为 `weak_ptr` 不保证对象还活着。`lock()` 的意义是：

1. 如果对象还存在，拿到一个临时 `shared_ptr`。
2. 如果对象已经销毁，得到空结果。

所以它是一个安全的“观察者转临时拥有者”动作。

### 4. 为什么 `unique_ptr` 默认不能拷贝

因为拷贝意味着两个对象同时认为自己拥有同一份独占资源，这和“独占所有权”矛盾。它只能通过移动把 ownership 转移出去。

## 正确写法 vs 常见错误写法

| 场景 | 正确写法 | 常见错误写法 | 为什么错 |
| --- | --- | --- | --- |
| 默认所有权 | 优先 `unique_ptr` | 默认上来就 `shared_ptr` | 共享所有权边界更难推理 |
| 循环关系 | `shared_ptr` + `weak_ptr` | 两边都用 `shared_ptr` | 会形成引用环，导致泄漏 |
| 观察对象 | 裸指针/引用/`weak_ptr` 视语义选择 | 用 `shared_ptr` 只是为了“方便拿着” | 会无意延长生命周期 |
| 访问 `weak_ptr` | `if (auto p = wp.lock())` | 直接假设对象一定还在 | 对象可能已经被释放 |
| 构造方式 | `make_unique` / `make_shared` | 手写 `new` 再塞进智能指针 | 异常和可读性都更差 |
| C 资源释放 | 智能指针 + 自定义 deleter | 把 `malloc` 出来的内存交给默认 `delete` | 释放方式不匹配，未定义行为 |

## 边界条件与适用范围

1. 智能指针主要解决所有权和自动释放问题，不自动解决逻辑边界设计问题。
2. `shared_ptr` 只适合真正需要共享生命周期的对象，不该拿来替代一切指针关系。
3. 裸指针并不是“被淘汰”，它仍然很适合表达不拥有的观察语义。
4. `unique_ptr` 适合树形或层级型资源结构，往往比共享关系更清晰。
5. 对性能极敏感路径，智能指针的额外成本和语义仍需结合场景权衡，但默认工程收益通常更大。

## 常见坑与排查

| 现象 | 常见根因 | 优先验证方法 |
| --- | --- | --- |
| 对象一直不析构 | `shared_ptr` 循环引用 | 画所有权图，检查是否应改为 `weak_ptr` |
| 生命周期比预期长 | 某处多持有了一个 `shared_ptr` | 检查谁在延长引用计数 |
| 访问对象时为空 | `weak_ptr` 对象已失效 | 看 `lock()` 返回是否为空 |
| 独占对象被复制失败 | `unique_ptr` 被误拷贝 | 改为 `std::move` 或重新设计所有权 |
| 崩溃或未定义行为 | 释放方式和资源来源不匹配 | 检查 deleter 和资源创建方式 |
| 代码越来越难懂 | 智能指针类型选错，所有权不清 | 回到 ownership 设计重画边界 |

### 推荐排查顺序

1. 先确认这个对象到底该独占、共享还是只观察。
2. 再检查当前指针类型是否真的表达了这个语义。
3. 再检查是否存在循环引用。
4. 再检查释放方式是否和创建方式匹配。
5. 最后再看更细的线程安全和性能问题。

## 工程落地建议

### 1. 默认所有权策略

推荐默认顺序：

1. 栈对象。
2. `std::vector`、`std::string` 等容器。
3. `std::unique_ptr`。
4. 必要时才 `std::shared_ptr`。

### 2. 接口设计建议

1. 返回新建对象时，优先返回 `unique_ptr`。
2. 借用对象时，优先用引用或裸指针表达非拥有语义。
3. 只有确实需要跨多个 owner 共享生命周期时，才把接口设计成 `shared_ptr`。

### 3. 和 C 接口配合的建议

1. C 接口返回 `malloc` 内存时，用 `unique_ptr<T, Deleter>` 封装。
2. C 接口要求调用专用释放函数时，把那个函数写进 deleter。
3. 把裸句柄尽快包进 RAII 边界，而不是让它在项目里裸奔。

## 性能、稳定性、可维护性影响

1. `unique_ptr` 成本低、语义清晰，通常是最稳妥的默认选择。
2. `shared_ptr` 虽然方便，但会让生命周期推理更复杂，维护成本明显更高。
3. `weak_ptr` 不是可有可无，它在共享图结构里是稳定性关键工具。
4. 真正可维护的 C++ 代码，不是智能指针用得越多越好，而是所有权边界越清楚越好。

## 面试 / 问答怎么讲

### 30 秒版本

智能指针的核心不是代替裸指针，而是表达所有权。`unique_ptr` 表示独占所有权，默认优先；`shared_ptr` 表示共享所有权，只在确实需要共享生命周期时使用；`weak_ptr` 表示观察不拥有，主要用来打破循环引用。

### 3 分钟版本

可以从所有权模型讲：现代 C++ 不推荐默认手写 `new/delete`，而是把资源交给智能指针。`unique_ptr` 适合清晰的单一 owner，性能和可推理性都更好；`shared_ptr` 适合共享生命周期，但有引用计数开销，也容易形成循环引用；`weak_ptr` 不增加计数，通过 `lock()` 安全观察对象。再补充自定义 deleter 如何封装 C 资源，讲法就比较完整。

### 10 分钟版本

可以进一步结合一个对象图案例展开：父子层级适合 `unique_ptr`，图结构或观察关系要谨慎用 `shared_ptr` 和 `weak_ptr`。再说明为什么默认上共享所有权会让系统变复杂、为什么循环引用会泄漏、为什么 `weak_ptr::lock()` 是安全观察入口。这种讲法会更贴近真实工程设计。

## 实战练习

1. 把一个手写 `new/delete` 的工厂函数改成返回 `std::unique_ptr`。
2. 写一个双向关系示例，分别用全 `shared_ptr` 和 `shared_ptr + weak_ptr` 实现，对比析构结果。
3. 用 `unique_ptr + 自定义 deleter` 封装一个 `FILE*` 或 `malloc` 返回指针。
4. 给一段现有类关系画出所有权图，判断哪些应该独占、哪些应该共享、哪些只应观察。

## 关键要点

1. 智能指针首先是所有权工具，不是语法糖。
2. `unique_ptr` 默认优先，`shared_ptr` 谨慎使用。
3. `weak_ptr` 的最大价值是打破引用环和安全观察。
4. 裸指针在现代 C++ 里更适合表达借用，不适合默认拥有资源。
5. 所有权语义越清晰，智能指针越能真正发挥价值。
