# 通信协议-RS232与RS485

## 原始问题

为什么串口通信有时候用RS232,有时候用RS485？它们到底有什么区别？工业现场为什么更常用RS485？如何设计稳定的RS485总线系统，而不是只会"接上线试试看"？

## 先给结论

RS232和RS485的核心区别，不是"哪个更好"，而是它们解决的问题场景不同：RS232适合短距离点对点，RS485适合长距离多设备总线。

先记住下面几个结论：

1. RS232是单端信号，传输距离短(15米内)，只能点对点通信，抗干扰能力弱。
2. RS485是差分信号，传输距离远(1200米)，支持多设备总线(最多128个)，抗干扰能力强。
3. RS232的电平标准是±3V到±15V，RS485是差分电压±200mV即可识别。
4. 工业现场优先选RS485，因为它能应对长距离、强干扰、多设备的恶劣环境。
5. RS485总线设计的核心是终端电阻、偏置电阻、接地和收发控制，而不是只关注TX/RX接线。

如果只知道"RS485比RS232远"，却讲不清差分信号原理、为什么要加终端电阻、半双工如何控制收发方向、总线冲突如何避免，就说明这部分还没有真正掌握。

## 这个知识解决什么问题

这篇笔记主要解决下面几类问题：

1. 项目选型时不知道该用RS232还是RS485。
2. RS485总线通信不稳定，偶发丢包、乱码、冲突。
3. 面试或工作中经常被问到"RS232和RS485的区别""RS485为什么要加终端电阻"。
4. 不知道如何设计可靠的RS485总线拓扑和硬件电路。

它在AI时代仍然重要，因为AI可以很快生成一段串口收发代码，但它不知道你的现场距离是否超标、是否需要隔离、终端电阻阻值该选多少、偏置电阻如何配置。RS485工程能力越扎实，你越能把AI生成的代码变成真正能在工业现场长期稳定运行的方案。

## 核心概念 / 本质机制

### 1. RS232的本质：单端信号

RS232使用单端信号传输，即信号线相对于地线的电压。

电平标准：
- 逻辑1(MARK)：-3V到-15V
- 逻辑0(SPACE)：+3V到+15V
- 无效区：-3V到+3V

特点：
1. 实现简单，成本低。
2. 传输距离短，典型15米内。
3. 抗干扰能力弱，容易受地线干扰。
4. 只能点对点通信，不支持多设备。

典型应用：
- PC串口调试
- 短距离设备通信
- 嵌入式调试日志输出

### 2. RS485的本质：差分信号

RS485使用差分信号传输，即两根信号线(A/B或D+/D-)之间的电压差。

电平标准：
- 逻辑1：A-B > +200mV
- 逻辑0：A-B < -200mV
- 发送端输出：±1.5V到±5V

差分信号的优势：
1. 共模干扰抑制：两根线受到相同干扰时，差值不变。
2. 传输距离远：差分信号衰减慢，可达1200米。
3. 抗干扰能力强：适合工业现场的强电磁环境。
4. 支持多设备总线：最多128个设备共享总线。

### 3. 为什么RS485能传得更远

差分信号的核心优势是共模抑制：

```text
假设干扰电压为+1V同时加到A和B线上：
A线：+2V + 1V = +3V
B线：-2V + 1V = -1V
差值：+3V - (-1V) = +4V (不变)
```

而单端信号RS232：
```text
信号线：+5V + 1V = +6V
地线：0V + 1V = +1V
差值：+6V - 1V = +5V (变化了)
```

所以RS485对共模干扰(如地电位差、电磁干扰)有天然抑制能力。

### 4. RS232 vs RS485对比

| 特性 | RS232 | RS485 |
| --- | --- | --- |
| 信号类型 | 单端 | 差分 |
| 电平标准 | ±3V到±15V | ±200mV(接收)，±1.5V(发送) |
| 传输距离 | 15米 | 1200米 |
| 传输速率 | 20kbps(15米) | 10Mbps(12米)，100kbps(1200米) |
| 设备数量 | 1对1 | 最多128个 |
| 抗干扰能力 | 弱 | 强 |
| 通信方式 | 全双工 | 半双工(2线)或全双工(4线) |
| 典型应用 | PC调试、短距离 | 工业总线、长距离 |

### 5. RS485的半双工与全双工

RS485有两种工作模式：

**半双工(2线制)**
- 只有A/B两根信号线
- 同一时刻只能发送或接收
- 需要软件控制收发方向(DE/RE引脚)
- 成本低，最常用

**全双工(4线制)**
- 有两对差分线(TX+/TX-和RX+/RX-)
- 可以同时收发
- 不需要控制收发方向
- 成本高，较少用

工业现场90%以上使用半双工2线制。

### 6. 为什么RS485需要终端电阻

RS485总线是传输线，信号在线上传播时会产生反射。

终端电阻的作用：
1. 匹配传输线特性阻抗(典型120Ω)
2. 吸收信号反射，避免波形畸变
3. 提高信号质量，减少误码

终端电阻位置：
- 总线两端各加一个120Ω电阻
- 中间节点不加

错误做法：
- 每个设备都加终端电阻(会导致负载过重)
- 不加终端电阻(长距离高速通信会失败)

### 7. 为什么RS485需要偏置电阻

RS485总线空闲时(所有设备都不发送)，A/B线处于高阻态，电压不确定，容易误触发。

偏置电阻的作用：
1. 上拉电阻(A线接VCC)：保证空闲时A > B
2. 下拉电阻(B线接GND)：保证空闲时A > B
3. 典型阻值：510Ω到1kΩ

偏置电阻位置：
- 通常在主机端或总线一端
- 不是每个设备都加

## 数据流 / 控制流 / 时序关系

### RS232通信流程

```text
发送端UART
-> TX引脚输出单端信号(±12V)
-> 接收端RX引脚采样
-> 接收端UART解析
```

### RS485半双工通信流程

```text
主机准备发送
-> 拉高DE(发送使能)
-> UART TX输出数据
-> RS485驱动芯片转换为差分信号(A/B)
-> 总线传输
-> 从机RS485接收芯片转换为单端信号
-> 从机UART RX接收
-> 主机发送完成，拉低DE，拉低RE(接收使能)
-> 从机准备应答，拉高DE
-> 从机发送应答
-> 主机接收应答
```

关键时序：
1. DE拉高后需要延迟几微秒再发送数据(驱动芯片使能时间)
2. 发送完成后需要延迟几微秒再拉低DE(最后一个字节发送完成时间)
3. 同一时刻只能有一个设备拉高DE，否则总线冲突

## 最小可运行示例

### RS232硬件连接

```text
设备A          设备B
TX    -------> RX
RX    <------- TX
GND   <------> GND
```

注意：
- 交叉连接：A的TX接B的RX
- 共地：GND必须连接

### RS485硬件连接(半双工)

```text
主机                从机1              从机2
A ----+----+----+---- A ----+----+---- A
      |    |    |           |    |
     120Ω  |   510Ω         |   120Ω
      |    |    |           |    |
B ----+----+----+---- B ----+----+---- B
           |    |                 |
          GND  510Ω              GND
```

关键点：
1. 总线两端各加120Ω终端电阻
2. 主机端加偏置电阻(A上拉，B下拉)
3. 所有设备共地(可选，但建议)

### RS485收发控制代码(STM32示例)

```c
/* 半双工RS485收发控制 */
#define RS485_DE_PIN    GPIO_PIN_1
#define RS485_RE_PIN    GPIO_PIN_2

/* 使能发送 */
static void rs485_tx_enable(void)
{
    HAL_GPIO_WritePin(GPIOA, RS485_DE_PIN, GPIO_PIN_SET);
    HAL_GPIO_WritePin(GPIOA, RS485_RE_PIN, GPIO_PIN_SET);
    /* 延迟等待驱动芯片使能 */
    delay_us(10);
}

/* 使能接收 */
static void rs485_rx_enable(void)
{
    /* 延迟等待最后一个字节发送完成 */
    delay_us(100);
    HAL_GPIO_WritePin(GPIOA, RS485_DE_PIN, GPIO_PIN_RESET);
    HAL_GPIO_WritePin(GPIOA, RS485_RE_PIN, GPIO_PIN_RESET);
}

/* 发送数据 */
int rs485_send(const uint8_t *data, uint16_t len)
{
    rs485_tx_enable();
    HAL_UART_Transmit(&huart1, data, len, 1000);
    rs485_rx_enable();
    return 0;
}

/* 接收数据(中断方式) */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart1) {
        /* 处理接收到的数据 */
        process_rx_data(rx_buffer, rx_len);
        /* 重新使能接收 */
        HAL_UART_Receive_IT(&huart1, rx_buffer, RX_BUF_SIZE);
    }
}
```

### RS485驱动芯片选型

常用芯片：
- MAX485：最经典，±15kV ESD保护
- MAX3485：3.3V供电，低功耗
- SP3485：±15kV ESD，更强抗干扰
- ADM2587E：隔离型，2.5kV隔离电压

典型电路(MAX485)：
```text
MCU                MAX485              总线
TX  -----------> DI
RX  <----------- RO
DE  -----------> DE
RE  -----------> /RE
                  A  -----------> A
                  B  -----------> B
                 GND -----------> GND
```

## 代码解读

### 1. 为什么发送前要延迟

RS485驱动芯片从接收模式切换到发送模式需要时间(典型1-10μs)，如果立即发送数据，第一个字节可能丢失。

### 2. 为什么发送后要延迟

UART发送函数返回时，最后一个字节可能还在移位寄存器中，如果立即切换到接收模式，最后一个字节可能被截断。

延迟时间计算：
```
字节时间 = (1起始位 + 8数据位 + 1停止位) / 波特率
例如9600bps: 10 / 9600 ≈ 1.04ms
```

保险做法是延迟2-3个字节时间。

### 3. 为什么DE和RE要同时控制

大部分RS485芯片的DE(发送使能)和/RE(接收使能，低电平有效)是独立的：
- DE=1, /RE=1：发送模式
- DE=0, /RE=0：接收模式
- DE=0, /RE=1：高阻态(既不发送也不接收)

有些芯片DE和/RE是内部连接的，只需要控制一个引脚。

### 4. 为什么主从协议适合RS485

RS485是半双工总线，同一时刻只能有一个设备发送，所以天然适合主从协议：
- 主机发起请求，从机应答
- 避免总线冲突
- 时序确定，便于调试

如果多个设备同时发送，会导致总线冲突，数据损坏。

## 正确写法 vs 常见错误写法

| 场景 | 正确写法 | 常见错误写法 | 为什么错 |
| --- | --- | --- | --- |
| 终端电阻 | 总线两端各加120Ω | 每个设备都加或不加 | 负载过重或信号反射 |
| 偏置电阻 | 主机端A上拉B下拉 | 不加偏置电阻 | 空闲时总线电压不确定 |
| 收发控制 | 发送前后延迟 | 立即切换 | 首尾字节丢失 |
| 接地 | 所有设备共地 | 不接地 | 地电位差导致通信失败 |
| 总线拓扑 | 手拉手菊花链 | 星型或树型 | 信号反射严重 |
| 通信协议 | 主从协议 | 多主竞争 | 总线冲突 |

## 边界条件与适用范围

### RS232适用场景
1. 短距离(15米内)点对点通信
2. 调试日志输出
3. PC与单个设备通信
4. 低速率、低成本场景

### RS485适用场景
1. 长距离(1200米内)通信
2. 多设备总线(最多128个)
3. 工业现场强干扰环境
4. Modbus、Profibus等工业协议

### 距离与速率的权衡

| 距离 | 最大速率 |
| --- | --- |
| 12米 | 10Mbps |
| 120米 | 1Mbps |
| 1200米 | 100kbps |

距离越远，速率越低，这是传输线损耗和信号衰减的物理限制。

## 常见坑与排查

| 现象 | 常见根因 | 优先验证方法 |
| --- | --- | --- |
| 短距离正常，长距离失败 | 没加终端电阻；速率过高 | 加终端电阻；降低波特率 |
| 偶发通信失败 | 没加偏置电阻；接地不良 | 加偏置电阻；检查接地 |
| 首字节或尾字节丢失 | 收发切换延迟不够 | 增加延迟时间 |
| 总线冲突 | 多设备同时发送 | 检查主从协议；检查DE控制 |
| 某些设备收不到 | 总线负载过重；终端电阻错 | 检查设备数量；检查终端电阻 |
| 波形畸变 | 终端电阻阻值错；线缆质量差 | 示波器测波形；换线缆 |

### 推荐排查顺序

1. 先确认硬件连接：A/B是否接对，终端电阻是否正确。
2. 再用示波器看差分信号波形，确认信号质量。
3. 再检查收发控制时序，确认DE/RE切换正确。
4. 再检查协议层，确认主从时序和超时处理。
5. 最后检查接地和屏蔽，确认抗干扰措施。

## 工程落地建议

### 1. 硬件设计检查清单

- [ ] 总线两端各加120Ω终端电阻
- [ ] 主机端加偏置电阻(A上拉510Ω，B下拉510Ω)
- [ ] 所有设备共地或隔离
- [ ] 使用双绞线，屏蔽线更佳
- [ ] 手拉手菊花链拓扑，避免星型
- [ ] 驱动芯片选型考虑ESD保护和隔离

### 2. 软件设计检查清单

- [ ] 发送前拉高DE，延迟10μs
- [ ] 发送后延迟2-3个字节时间再拉低DE
- [ ] 使用主从协议，避免总线冲突
- [ ] 超时重试机制
- [ ] 异常恢复机制
- [ ] 日志记录收发时序和错误

### 3. 现场调试建议

1. 先用短线(1-2米)验证功能
2. 再逐步增加距离，观察信号质量
3. 用示波器测量差分信号波形
4. 用逻辑分析仪抓取协议帧
5. 模拟干扰(如变频器、电机)测试抗干扰能力

### 4. 隔离设计

工业现场建议使用隔离型RS485芯片或隔离模块：
1. 隔离电压：1kV到2.5kV
2. 隔离方式：光耦、磁耦或电容隔离
3. 隔离电源：DC-DC隔离电源
4. 典型芯片：ADM2587E、ADUM1201

隔离的作用：
1. 保护MCU免受总线高压冲击
2. 隔断地环路，避免地电位差
3. 提高系统可靠性

## 性能、稳定性、可维护性影响

1. RS485总线设计不当，会导致通信不稳定、偶发丢包、难以排查。
2. 终端电阻和偏置电阻是RS485稳定性的关键，不能省略。
3. 收发控制时序不正确，会导致首尾字节丢失，难以发现。
4. 主从协议设计不当，会导致总线冲突，系统瘫痪。

## 面试 / 问答怎么讲

### 30秒版本

RS232是单端信号，短距离点对点，抗干扰弱。RS485是差分信号，长距离多设备总线，抗干扰强。工业现场优先选RS485，因为它能应对1200米距离、128个设备和强电磁干扰。RS485总线设计的关键是终端电阻、偏置电阻和收发控制。

### 3分钟版本

可以先讲RS232和RS485的电气特性差异：单端vs差分，电平标准，传输距离。然后讲RS485的优势：差分信号抑制共模干扰，支持多设备总线。再讲RS485硬件设计要点：总线两端加120Ω终端电阻，主机端加偏置电阻，手拉手菊花链拓扑。最后讲软件设计：半双工需要控制DE/RE，发送前后要延迟，使用主从协议避免冲突。

### 10分钟版本

可以进一步结合真实项目展开，比如工业现场用RS485连接多个传感器。讲清差分信号的共模抑制原理，为什么能传1200米。然后讲终端电阻的作用：匹配特性阻抗，吸收信号反射。再讲偏置电阻的作用：保证空闲时总线电压确定。接着讲收发控制时序：为什么要延迟，延迟多久。最后讲一个实际排障案例，比如长距离通信失败，如何通过示波器定位是终端电阻问题还是速率过高。这种讲法更像真实工程能力。

## 实战练习

1. 用RS232连接两个开发板，实现简单的串口通信。
2. 用RS485连接3个开发板，实现主从通信(1主2从)。
3. 用示波器测量RS485差分信号波形，对比加不加终端电阻的差异。
4. 故意制造总线冲突(两个设备同时发送)，观察现象并设计避免方案。
5. 测试RS485的最大传输距离和速率，绘制距离-速率曲线。

## 关键要点

1. RS232单端信号，短距离点对点；RS485差分信号，长距离多设备。
2. RS485差分信号抑制共模干扰，适合工业现场。
3. RS485总线两端加120Ω终端电阻，主机端加偏置电阻。
4. 半双工RS485需要控制DE/RE，发送前后要延迟。
5. 使用主从协议避免总线冲突，手拉手菊花链拓扑避免信号反射。
