# 硬件-高速串行接口基础

## 原始问题

USB 3.0、PCIe、SATA、HDMI 这些高速接口为什么不用并行总线？SerDes 是什么？预加重和去加重有什么用？均衡器怎么补偿信号衰减？链路训练是什么过程？8b/10b 和 128b/130b 编码有什么区别？

## 先给结论

高速串行接口的核心是"用少数几对差分线、通过极高频率的串行传输，替代大量并行线"：

1. 并行总线受限于时钟偏斜和信号数量，频率难以提升；串行接口用差分信号 + 嵌入式时钟突破了这个瓶颈。
2. SerDes（串行器/解串器）是高速串行接口的核心电路，完成并行数据和串行比特流之间的转换。
3. 信号经过 PCB 走线和连接器后会衰减和失真，预加重/去加重在发送端预补偿，均衡器在接收端后补偿。
4. 链路训练是收发双方协商速率、补偿参数和建立同步的过程。
5. 8b/10b 等编码保证足够的跳变密度，让接收端能恢复时钟。

如果只知道"USB 和 PCIe 是高速接口"，但讲不清为什么用串行、SerDes 做了什么、预加重和均衡的原理、链路训练的过程，就还没有真正理解高速串行接口。

## 这个知识解决什么问题

这篇笔记主要解决下面几类问题：

1. 不理解为什么高速接口都从并行转向串行。
2. 面试时被问"SerDes 是什么"，讲不清原理。
3. 不理解预加重、去加重、均衡器的作用。
4. 不知道链路训练是什么，调试高速接口时不知道怎么排查。
5. 不理解 8b/10b 编码为什么需要，以为只是浪费带宽。

它在 AI 时代依然重要，因为 AI 能帮你写 USB/PCIe 驱动代码，但当高速链路不稳定时，AI 无法帮你分析是预加重不够、均衡参数不对、还是 PCB 走线有问题。理解高速串行接口的物理层原理后，你才能在"驱动代码没问题但链路不稳定"时，把调试方向转向物理层参数。

## 核心概念 / 本质机制

### 1. 为什么从并行转向串行

并行总线的瓶颈：

```text
1. 时钟偏斜 (Clock Skew):
   多根数据线的传播延迟不同
   → 频率越高，采样窗口越小
   → 偏斜占采样窗口的比例越大
   → 频率难以提升

2. 信号数量:
   32 位并行 = 32 根数据线 + 时钟 + 控制
   → PCB 布线困难
   → 连接器引脚多
   → 成本高

3. 同步开关噪声 (SSN):
   多根信号同时翻转
   → 电源/地弹噪声大
   → 信号完整性差
```

串行接口的优势：

```text
1. 无时钟偏斜:
   时钟嵌入在数据流中 (CDR 恢复)
   → 不需要同步多根线

2. 引脚少:
   1 对差分线 = 2 个引脚
   → 连接器小、成本低

3. 差分信号:
   抗干扰能力强
   → 适合高速长距离传输

4. 可扩展:
   多 lane 并行扩展带宽
   → PCIe x1/x2/x4/x8/x16
```

### 2. SerDes 架构

SerDes = Serializer（串行器）+ Deserializer（解串器）

```text
发送方向 (TX):

并行数据 (32/64 bit)
  |
  V
编码器 (8b/10b 或 128b/130b)
  |
  V
串行器 (PISO: Parallel In, Serial Out)
  |
  V
预加重 / 去加重
  |
  V
差分驱动器
  |
  V
差分信号对 (TX+ / TX-)


接收方向 (RX):

差分信号对 (RX+ / RX-)
  |
  V
差分接收器
  |
  V
均衡器 (CTLE / DFE)
  |
  V
CDR (Clock and Data Recovery)
  |
  V
解串器 (SIPO: Serial In, Parallel Out)
  |
  V
解码器 (8b/10b 或 128b/130b)
  |
  V
并行数据 (32/64 bit)
```

### 3. CDR（时钟数据恢复）

CDR 从数据流中恢复时钟，不需要单独的时钟线：

```text
原理:
  1. 数据流经过编码后保证足够的跳变密度
  2. CDR 中的 PLL 锁定数据跳变沿
  3. 恢复出与数据同步的时钟
  4. 用恢复的时钟采样数据

关键要求:
  数据流必须有足够的跳变 (0→1 或 1→0)
  → 如果长时间没有跳变，CDR 会失锁
  → 这就是为什么需要 8b/10b 等编码
```

### 4. 8b/10b 编码

8b/10b 编码把 8 位数据编码为 10 位传输：

```text
编码规则:
  8 位数据 → 查表 → 10 位编码
  保证:
  1. 连续 0 或 1 不超过 5 个 (游程长度限制)
  2. 0 和 1 的数量基本平衡 (DC 平衡)
  3. 有足够的跳变密度供 CDR 使用

代价:
  带宽开销: 10/8 = 1.25，即 20% 的带宽用于编码开销
  实际数据速率 = 线速率 × 80%

示例:
  PCIe Gen1: 线速率 2.5GT/s
  数据速率: 2.5 × 0.8 = 2.0Gb/s (每 lane)
```

### 5. 128b/130b 编码

128b/130b 用于更高速的接口（PCIe Gen3+、USB 3.1+）：

```text
编码规则:
  128 位数据 + 2 位同步头 → 130 位传输
  开销: 130/128 = 1.016，仅 1.6%

优势:
  带宽利用率高 (98.4% vs 80%)
  适合更高速率

代价:
  游程长度限制不如 8b/10b 严格
  需要更强大的 CDR 和均衡

示例:
  PCIe Gen3: 线速率 8.0GT/s
  数据速率: 8.0 × 128/130 ≈ 7.88Gb/s (每 lane)
```

### 6. 信道损耗与补偿

高速信号经过 PCB 走线和连接器后会衰减：

```text
损耗来源:
1. 导体损耗: 走线电阻，与频率的平方根成正比
2. 介质损耗: PCB 材料的介电损耗，与频率成正比
3. 阻抗不连续: 过孔、连接器引起的反射
4. 串扰: 相邻走线的耦合

高频分量衰减更多 → 信号边沿变圆 → 码间干扰 (ISI)

补偿方法:
  发送端: 预加重 / 去加重
  接收端: 均衡器 (CTLE / DFE)
```

### 7. 预加重与去加重

```text
预加重 (Pre-emphasis):
  信号跳变时增大驱动幅度
  → 补偿信道对高频分量的衰减
  → 让接收端看到更清晰的边沿

去加重 (De-emphasis):
  信号不跳变时减小驱动幅度
  → 效果等同于预加重
  → 实现更简单，更常用

典型去加重值:
  -3dB: 信号不跳变时幅度降低到 70%
  -6dB: 信号不跳变时幅度降低到 50%
  -9dB: 信号不跳变时幅度降低到 35%

选择原则:
  信道损耗大 → 去加重值大
  信道损耗小 → 去加重值小
  需要通过仿真和实测确定最佳值
```

### 8. 均衡器

接收端的均衡器补偿信道损耗：

```text
CTLE (Continuous Time Linear Equalizer):
  高通滤波器，放大高频分量
  → 补偿信道的低通特性
  → 简单但可能放大噪声

DFE (Decision Feedback Equalizer):
  根据已判决的比特反馈消除 ISI
  → 不放大噪声
  → 更复杂但效果更好

典型组合:
  CTLE + DFE 联合使用
  CTLE 做粗补偿，DFE 做精细补偿
```

### 9. 链路训练

链路训练是收发双方协商参数并建立同步的过程：

```text
PCIe 链路训练过程:

1. 检测对端设备 (Receiver Detection)
   → 确认对端存在

2. 协商速率和宽度
   → 从最低速率开始，逐步提升
   → 协商 lane 数量 (x1/x2/x4/...)

3. 位锁定 (Bit Lock)
   → CDR 锁定接收数据流的时钟

4. 符号锁定 (Symbol Lock)
   → 识别 8b/10b 或 128b/130b 的符号边界

5. 通道对齐 (Lane Alignment)
   → 多 lane 时对齐各 lane 的数据

6. 均衡调节
   → 交换均衡参数 (Preset)
   → 调节预加重和 CTLE/DFE 参数
   → 直到误码率满足要求

7. 链路就绪
   → 进入正常数据传输模式
```

链路训练失败的可能原因：

1. 信号完整性差（阻抗不匹配、走线太长）。
2. 均衡参数不合适。
3. 参考时钟不稳定。
4. 对端设备未正确初始化。
5. 电源噪声大。

### 11. 软件工程师需要关注的高速接口知识

1. **链路训练失败**：驱动 probe 时链路训练不过，可能是硬件问题而不是驱动问题。
2. **速率协商**：设备支持多速率时，驱动需要正确配置速率。
3. **均衡参数**：某些接口允许软件配置预加重和均衡参数。
4. **误码率**：高速接口的误码率要求通常 < 10⁻¹²，软件层面可能看不到错误。
5. **电源管理**：高速接口的省电模式（如 PCIe L0s/L1）需要软件配合。

## 数据流 / 控制流 / 时序关系

### 高速串行传输的完整数据流

```text
应用层数据
  |
  V
协议层 (添加协议头/尾, 如 PCIe TLP)
  |
  V
事务层 (重试、排序)
  |
  V
数据链路层 (添加序列号、CRC、8b/10b 编码)
  |
  V
物理层 (SerDes 串行化、预加重、差分驱动)
  |
  V
PCB 走线 + 连接器 (信道衰减、反射、串扰)
  |
  V
物理层 (差分接收、均衡、CDR、解串、解码)
  |
  V
数据链路层 (CRC 校验、重传)
  |
  V
事务层
  |
  V
协议层
  |
  V
应用层数据
```

### 链路训练的时序

```text
时间线:

0ms:    设备上电，PHY 复位释放
        |
1ms:    发送端开始发送训练序列 (TS1/TS2)
        |
5ms:    接收端 CDR 开始锁定
        |
10ms:   位锁定完成
        |
15ms:   符号锁定完成
        |
20ms:   均衡调节开始
        |
30ms:   均衡调节完成
        |
35ms:   链路训练完成，进入 L0 状态
        |
40ms+:  正常数据传输
```

## 最小可运行示例

### PCIe 链路状态检查

```bash
# 查看 PCIe 链路速率和宽度
lspci -vv | grep -E "LnkCap|LnkSta"

# 输出示例:
# LnkCap: Port #0, Speed 8GT/s, Width x4, ASPM L0s L1
# LnkSta: Speed 8GT/s, Width x4, ASPM L0s L1

# 如果 Speed 低于 LnkCap 的值，说明链路训练协商到了较低速率
# 可能原因: 信号完整性差、均衡参数不对、走线太长
```

### USB 3.0 链路状态

```bash
# 查看 USB 设备速率
lsusb -t

# 输出示例:
#     |__ Port 1: Dev 2, If 0, Class=..., Driver=xhci_hcd, 5000M
#     5000M = USB 3.0 (5Gbps)
#     480M  = USB 2.0
#     12M   = USB 1.1

# 如果 USB 3.0 设备显示 480M，说明链路训练回退到了 USB 2.0
# 可能原因: 信号完整性差、SSRX/SSTX 连接问题
```

### 设备树中的 PCIe 配置

```dts
&pcie0 {
    status = "okay";

    /* 最大支持的链路速率 */
    max-link-speed = <3>;  /* Gen3 = 8GT/s */

    /* lane 数量 */
    num-lanes = <4>;

    /* ASPM 配置 */
    aspm-no-l0s;           /* 禁用 L0s，某些设备不兼容 */

    /* 参考时钟配置 */
    clocks = <&cru CLK_PCIE_PHY>, <&cru ACLK_PCIE>;
    clock-names = "phy", "bus";

    /* 电源域 */
    power-domains = <&power PCIE_PD>;

    /* 重置线 */
    resets = <&cru SRST_PCIE_PHY>;
    reset-names = "phy";
};
```

## 代码解读

### 1. 为什么 USB 3.0 设备可能回退到 USB 2.0

USB 3.0 有两套信号线：USB 2.0 的 D+/D- 和 USB 3.0 的 SSTX+/SSTX-/SSRX+/SSRX-。如果 USB 3.0 的差分对连接有问题（走线太长、阻抗不匹配、连接器接触不良），链路训练会失败，设备自动回退到 USB 2.0 模式。此时设备仍然能工作，但速度大幅降低。

### 2. 为什么 PCIe ASPM L0s 可能需要禁用

L0s 是 PCIe 的低功耗状态，发送端可以独立进入 L0s 节省功耗。但某些设备从 L0s 唤醒时会出现问题（时序不满足、链路训练失败）。`aspm-no-l0s` 禁用 L0s，牺牲功耗换取稳定性。

### 3. 为什么 max-link-speed 需要配置

SoC 的 PCIe 控制器可能支持多种速率，但 PCB 走线可能不支持最高速率。通过 `max-link-speed` 限制最高速率，避免链路训练在高速率下反复失败。

## 正确写法 vs 常见错误写法

| 场景 | 正确做法 | 常见错误 | 为什么错 |
| --- | --- | --- | --- |
| PCIe 速率配置 | 根据走线质量限制最高速率 | 直接设最高速率 | 链路训练可能失败 |
| USB 3.0 调试 | 先确认 SS 信号连接 | 只看 D+/D- | USB 2.0 正常但 3.0 不工作 |
| ASPM 配置 | 不兼容设备禁用 L0s | 全部启用 | 某些设备唤醒异常 |
| 均衡参数 | 通过仿真和实测确定 | 随意设置 | 可能过补偿或欠补偿 |
| 差分走线 | 严格等长等距阻抗控制 | 不做阻抗控制 | 链路训练失败 |
| 链路训练失败排查 | 先降速率测试 | 只改驱动代码 | 可能是物理层问题 |

## 边界条件与适用范围

1. 这篇笔记面向软件工程师的高速接口入门，不是 SerDes 设计专业课程。
2. 高速接口的物理层调试需要专业设备（误码率测试仪、网络分析仪）。
3. 不同接口的链路训练过程差异很大，本篇以 PCIe 为例。
4. MIPI 接口（D-PHY/C-PHY）有独特的信令方式，不在本篇深入。
5. 实际高速接口调试通常需要硬件工程师和 SI 工程师配合。

## 常见坑与排查

| 现象 | 可能原因 | 优先验证方法 |
| --- | --- | --- |
| PCIe 链路训练失败 | 信号完整性差、参考时钟问题 | 降低速率测试 |
| USB 3.0 回退到 2.0 | SS 差分对连接问题 | 检查走线和连接器 |
| 高速接口偶发丢数据 | 均衡参数不对 | 调整预加重/均衡 |
| 链路训练时间长 | 信号质量差，多次重试 | 看训练日志 |
| ASPM 唤醒后异常 | 设备不兼容 L0s/L1 | 禁用 ASPM 测试 |
| 热插拔后不识别 | 热插拔检测电路问题 | 检查硬件检测信号 |

### 推荐排查顺序

1. 先确认物理连接是否正确（差分对是否接对）。
2. 再降低速率测试（降速后是否正常）。
3. 再检查参考时钟是否稳定。
4. 再检查电源是否干净（高速 PHY 对电源噪声敏感）。
5. 再调整均衡参数。
6. 最后用专业设备做眼图和误码率测试。

## 工程落地建议

### 1. 高速接口调试清单

```text
硬件检查:
  [ ] 差分对是否等长等距？
  [ ] 阻抗是否控制在规格范围内？
  [ ] 参考时钟是否稳定？
  [ ] 电源去耦是否充足？
  [ ] 连接器引脚是否正确？

软件检查:
  [ ] 设备树速率和宽度配置是否正确？
  [ ] ASPM 配置是否兼容？
  [ ] 驱动是否正确初始化 PHY？
  [ ] 链路训练日志是否正常？
```

### 2. 链路训练日志分析

```bash
# 启用 PCIe 调试日志
echo 1 > /sys/kernel/debug/tracing/events/nvme/enable
dmesg | grep -i pcie

# 关注:
# - 链路训练是否完成
# - 协商到的速率和宽度
# - 是否有错误恢复 (AER)
# - 是否有重训 (retrain)
```

### 3. 降速测试方法

```dts
/* 逐步降低速率测试 */
/* Gen3 (8GT/s) 不行 → 试 Gen2 (5GT/s) → 试 Gen1 (2.5GT/s) */
&pcie0 {
    max-link-speed = <1>;  /* 先试 Gen1 */
};
```

## 性能、稳定性、可维护性影响

1. 高速接口的物理层质量直接决定链路稳定性和最大带宽。
2. 链路训练失败是最常见的高速接口问题，降速可以临时解决但牺牲性能。
3. ASPM 省电模式与稳定性之间需要权衡，不兼容设备必须禁用。
4. 均衡参数需要针对每块板子优化，批量生产时可能需要参数校准。
5. 高速接口的误码通常是隐性的，需要长时间压力测试才能发现。

## 面试 / 问答怎么讲

### 30 秒版本

高速串行接口用差分信号 + 嵌入式时钟替代并行总线，突破时钟偏斜瓶颈。SerDes 完成并串/串并转换，CDR 从数据流恢复时钟。8b/10b 编码保证跳变密度，预加重和均衡补偿信道损耗，链路训练协商速率和参数。

### 3 分钟版本

从并行到串行的转变讲起：并行受时钟偏斜限制，串行用嵌入式时钟突破。然后讲 SerDes 架构：编码→串行化→预加重→差分驱动，接收端→均衡→CDR→解串→解码。再讲 8b/10b 编码：保证跳变密度和 DC 平衡，代价是 20% 带宽开销。再讲预加重和均衡：发送端预补偿高频，接收端后补偿衰减。最后讲链路训练：协商速率、锁定时钟、调节均衡、建立同步。

### 10 分钟版本

可以系统展开：先详细对比并行和串行的优缺点。然后深入 SerDes 架构的每个模块。再讲 8b/10b 和 128b/130b 编码的原理和区别。再讲信道损耗的物理机制和补偿方法（预加重、CTLE、DFE）。再讲链路训练的完整过程和失败排查。最后讲常见高速接口（USB 3.0、PCIe、SATA）的特点和调试方法。

## 实战练习

1. 在 Linux 上用 `lspci -vv` 查看 PCIe 设备的链路速率和宽度，对比能力和实际状态。
2. 用 `lsusb -t` 确认 USB 设备是否工作在 3.0 速率，如果不是，排查原因。
3. 修改设备树把 PCIe 速率从 Gen3 降到 Gen2，观察链路训练是否更稳定。
4. 在 dmesg 中查找 PCIe 链路训练日志，分析训练过程。
5. 禁用 PCIe ASPM，观察是否解决偶发的链路不稳定问题。

## 关键要点

1. 串行接口用差分信号 + 嵌入式时钟突破并行总线的时钟偏斜瓶颈。
2. SerDes 完成并串/串并转换，CDR 从数据流恢复时钟。
3. 8b/10b 编码保证跳变密度和 DC 平衡，代价是 20% 带宽开销；128b/130b 仅 1.6% 开销。
4. 预加重/去加重在发送端预补偿高频衰减，均衡器在接收端后补偿。
5. 链路训练协商速率、锁定时钟、调节均衡、建立同步。
6. 链路训练失败时先降速率测试，排除物理层问题。
7. ASPM 省电模式可能与某些设备不兼容，需要权衡。
