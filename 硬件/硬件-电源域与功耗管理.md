# 硬件-电源域与功耗管理

## 原始问题

SoC 为什么有那么多电源域？LDO、DCDC、PMIC 到底有什么区别？为什么有些模块单独供电？静态功耗和动态功耗分别是什么？低功耗模式到底关了什么？软件怎么配合硬件做功耗管理？

## 先给结论

电源域与功耗管理的核心是"不同模块需要不同的电压和供电策略"：

1. SoC 内部有多个电源域，每个域可以独立控制电压和开关。
2. LDO 是线性稳压，简单但效率低；DCDC 是开关稳压，效率高但需要电感和更复杂的外围。
3. PMIC 集成多路 LDO/DCDC，由 I2C/SPI 控制，是复杂 SoC 供电的主流方案。
4. 静态功耗是"不干活也在耗电"，主要来自漏电流；动态功耗是"干活时耗电"，跟频率和电压的平方成正比。
5. 低功耗设计的关键是：关掉不需要的模块、降低不需要的频率、降低不需要的电压。

如果只知道"芯片要供电"，但讲不清电源域划分、LDO 和 DCDC 的区别、功耗来源和降低策略，就还没有真正理解电源域与功耗管理。

## 这个知识解决什么问题

这篇笔记主要解决下面几类问题：

1. 看原理图时不知道为什么一个 SoC 有那么多电源引脚，每个域干什么用。
2. 不理解 LDO 和 DCDC 的区别，不知道什么时候用哪个。
3. 不知道功耗从哪来，做低功耗优化时无从下手。
4. 面试时被问"动态功耗和什么有关"，只能说出"频率"。
5. 不理解 Linux 电源管理框架和硬件电源域的关系。

它在 AI 时代依然重要，因为 AI 生成设备树和驱动代码时经常忽略电源域配置、不检查供电是否满足要求、不评估功耗影响。理解电源域和功耗管理后，你才能判断 AI 给的方案在电源层面是否正确、是否会导致过流或过热。

## 核心概念 / 本质机制

### 1. 为什么 SoC 需要多个电源域

不同模块对电压和供电策略的需求不同：

| 电源域 | 典型电压 | 为什么单独供电 |
| --- | --- | --- |
| VDD_CORE | 0.8V~1.2V | CPU 核心需要低电压降低功耗，频率可调需要调压 |
| VDD_IO | 1.8V / 3.3V | IO 电压由外部接口标准决定 |
| VDD_DDR | 1.2V / 1.35V | DDR 颗粒有固定电压要求 |
| VDD_ANA | 1.8V / 3.3V | 模拟电路需要干净电源，避免数字噪声耦合 |
| VDD_PHY | 各异 | USB/ETH 等 PHY 有独立供电要求 |
| VDD_RTC | 1.0V~3.3V | RTC 域在休眠时必须保持供电 |
| VDD_USB | 3.3V | USB PHY 需要独立供电和电源开关 |

独立供电的好处：

1. 可以单独关闭不需要的域，降低功耗。
2. 可以给不同域配不同电压，满足不同模块需求。
3. 可以隔离噪声，模拟域和数字域分开供电。
4. 可以独立调压，DVFS 需要核心域电压可调。

### 2. LDO（低压差线性稳压器）

LDO 的工作原理：

```text
输入电压 (Vin) --> [调整管 + 反馈环路] --> 输出电压 (Vout)
                      |
                  基准电压比较

Vout = Vref × (1 + R1/R2)
```

LDO 的特点：

1. 输入输出压差小（LDO = Low Dropout），典型压差 100~300mV。
2. 输出纹波小，适合给模拟电路和对噪声敏感的模块供电。
3. 效率 = Vout / Vin，压差越大效率越低。
4. 多余的功率全部变成热量：P_loss = (Vin - Vout) × I_load。

LDO 的选型参数：

| 参数 | 含义 | 典型值 |
| --- | --- | --- |
| 压差 (Dropout) | 维持稳压的最小输入输出差 | 100~500mV |
| 最大输出电流 | 能提供的最大负载电流 | 150mA~3A |
| PSRR | 电源抑制比，抑制输入纹波的能力 | 60~90dB |
| 噪声 | 输出电压的噪声密度 | 10~100μVrms |
| 静态电流 | 空载时 LDO 自身消耗的电流 | 1~100μA |

### 3. DCDC（开关稳压器 / 降压转换器）

DCDC 的工作原理（Buck 降压型）：

```text
输入电压 (Vin) --> [开关管 + 电感 + 续流二极管 + 电容] --> 输出电压 (Vout)

开关管以高频 (1~5MHz) 开关，电感储能和释能，电容平滑输出

Vout = Vin × D (D = 占空比)
```

DCDC 的特点：

1. 效率高，通常 85%~95%，跟压差关系不大。
2. 需要电感和电容，占 PCB 面积大。
3. 输出纹波比 LDO 大，开关噪声需要滤波。
4. 适合大电流、大压差场景。

DCDC 的选型参数：

| 参数 | 含义 | 典型值 |
| --- | --- | --- |
| 输入电压范围 | 支持的输入电压范围 | 2.7~5.5V |
| 输出电压 | 固定或可调 | 0.8~3.3V |
| 最大输出电流 | 能提供的最大负载电流 | 1~20A |
| 开关频率 | 内部开关管工作频率 | 1~5MHz |
| 效率 | 转换效率 | 85~95% |

### 4. LDO vs DCDC 选型对比

| 对比项 | LDO | DCDC |
| --- | --- | --- |
| 效率 | 低（压差大时） | 高 |
| 纹波 | 小 | 较大 |
| 噪声 | 低 | 有开关噪声 |
| 外围器件 | 只需输入输出电容 | 需要电感 + 电容 |
| PCB 面积 | 小 | 大 |
| 成本 | 低 | 较高 |
| 大电流能力 | 受限（发热） | 强 |
| 适用场景 | 小电流、低压差、低噪声 | 大电流、大压差、高效率 |

典型分配：

1. CPU 核心：DCDC（大电流、需要 DVFS 调压）。
2. DDR 供电：DCDC（大电流）。
3. IO 供电：LDO（小电流、低压差、低噪声）。
4. 模拟供电：LDO（低噪声、高 PSRR）。
5. RTC 供电：LDO（超低静态电流）。

### 5. PMIC（电源管理芯片）

PMIC 把多路 LDO/DCDC 集成在一个芯片里：

```text
PMIC (如 RK817 / AXP2101 / MP5416)

输入: VBAT (3.7V 锂电) 或 VDC (5V 适配器)

输出:
  DCDC1 -> VDD_CORE (0.9V, 2A)
  DCDC2 -> VDD_DDR  (1.2V, 2A)
  DCDC3 -> VDD_IO   (3.3V, 1A)
  LDO1  -> VDD_RTC  (1.0V, 10mA)
  LDO2  -> VDD_ANA  (1.8V, 150mA)
  LDO3  -> VDD_PHY  (3.3V, 200mA)
```

PMIC 的控制方式：

1. I2C / SPI 接口：软件读写寄存器控制输出电压、使能开关。
2. GPIO 控制：某些 LDO/DCDC 可以通过外部 GPIO 使能/禁能。
3. 状态输出：PGOOD（Power Good）信号指示输出是否稳定。
4. 中断输出：过流、过温、短路等异常通知。

### 6. 静态功耗与动态功耗

#### 静态功耗（Static Power / Leakage）

静态功耗是芯片不切换时的功耗，主要来源：

1. 亚阈值漏电流（Subthreshold Leakage）：MOS 管关断时仍有微小电流。
2. 栅极漏电流（Gate Leakage）：栅极氧化层的隧穿电流。
3. 结漏电流（Junction Leakage）：PN 结的反向漏电。

静态功耗特点：

1. 跟电压正相关：电压越高漏电越大。
2. 跟温度正相关：温度越高漏电越大。
3. 跟制程正相关：制程越先进漏电越严重（沟道越短）。
4. 不受频率影响。

降低静态功耗的方法：

1. 关断不需要的电源域（Power Gating）。
2. 降低电压。
3. 使用高阈值电压晶体管（HVT）。

#### 动态功耗（Dynamic Power / Switching Power）

动态功耗是芯片切换时的功耗：

```text
P_dynamic = α × C × V² × f

α: 活动因子（0~1，表示同时切换的晶体管比例）
C: 负载电容
V: 工作电压
f: 工作频率
```

关键结论：

1. 动态功耗跟电压的平方成正比 → 降电压效果最显著。
2. 动态功耗跟频率成正比 → 降频率也能降功耗。
3. 降电压比降频率更有效（二次方 vs 线性关系）。

### 7. DVFS（动态电压频率调节）

DVFS 的核心思想：性能需求低时，同时降低电压和频率，节省功耗。

```text
高性能模式: VDD_CORE = 1.2V, f = 1.8GHz, P ∝ 1.2² × 1.8G
平衡模式:   VDD_CORE = 1.0V, f = 1.2GHz, P ∝ 1.0² × 1.2G
省电模式:   VDD_CORE = 0.8V, f = 0.6GHz, P ∝ 0.8² × 0.6G
```

DVFS 的实现需要：

1. 可调压的 DCDC（通过 I2C 调 PMIC 寄存器）。
2. 可调频的 PLL（通过时钟控制器寄存器）。
3. 操作系统调度器配合（Linux 的 cpufreq 框架）。

调压顺序很重要：

```text
升频: 先升电压 → 等待稳定 → 再升频率
降频: 先降频率 → 再降电压
```

如果先升频率再升电压，CPU 可能在电压不够时以高频运行，导致不稳定甚至崩溃。

### 8. 低功耗模式

嵌入式系统常见的低功耗模式：

| 模式 | 关闭内容 | 唤醒方式 | 典型功耗 |
| --- | --- | --- | --- |
| Run | 无 | - | 100mA~数A |
| Idle / WFI | CPU 时钟停止 | 中断 | 略低于 Run |
| Sleep | CPU + 部分外设时钟 | 中断 / 事件 | 1~10mA |
| Deep Sleep | 大部分时钟和电源域关闭 | RTC / GPIO | 10~100μA |
| Standby | 仅 RTC 域保持供电 | RTC / 复位 | 1~10μA |
| Shutdown | 全部关闭 | 复位 / 按键 | < 1μA |

Cortex-M 的低功耗模式：

```text
Sleep:     执行 WFI/WFE，CPU 停止，外设继续运行
Stop:      CPU 和大部分外设停止，SRAM 保持
Standby:   仅 RTC 和备份域保持，SRAM 丢失
```

Cortex-A 的低功耗模式：

```text
WFI:       CPU 核心进入等待中断状态
CPU Idle:  单个 CPU 核心关闭
Retension: 核心状态保留在内部 SRAM
Power Off: 核心电源关闭，状态丢失
```

### 9. 电源域与设备树

Linux 中电源域由 genpd（Generic Power Domain）框架管理：

```dts
/* 电源域定义 */
power-domains {
    pd_core: power-domain@0 {
        #power-domain-cells = <0>;
    };
    pd_gpu: power-domain@1 {
        #power-domain-cells = <0>;
    };
};

/* 设备绑定电源域 */
gpu@ff300000 {
    compatible = "vendor,gpu";
    power-domains = <&pd_gpu>;
    power-domain-names = "gpu";
};
```

驱动中使用 runtime PM：

```c
pm_runtime_get_sync(dev);   /* 使用设备前，确保电源域开启 */
/* ... 使用设备 ... */
pm_runtime_put_sync(dev);   /* 使用完毕，允许电源域关闭 */
```

### 10. 上电时序

SoC 对上电时序有严格要求：

```text
典型上电顺序:

1. VDD_RTC    (始终供电，最先上电)
2. VDD_CORE   (CPU 核心供电)
3. VDD_DDR    (DDR 供电)
4. VDD_IO     (IO 供电)
5. VDD_PHY    (PHY 供电)

每一步之间需要延迟 (通常 1~10ms)
```

如果上电顺序错误：

1. 可能导致 IO 引脚在电压未稳定时输出不确定电平。
2. 可能导致核心逻辑在 IO 电压未建立时读取错误配置。
3. 可能导致 DDR 初始化失败。
4. 严重时可能损坏芯片。

PMIC 通常内置上电时序控制器，按预设顺序依次开启各路输出。

## 数据流 / 控制流 / 时序关系

### 上电到运行的完整流程

```text
按下电源键 / 插入电源
  |
  V
PMIC 检测到电源事件
  |
  V
PMIC 按预设时序依次开启各路输出
  VDD_RTC → VDD_CORE → VDD_DDR → VDD_IO → VDD_PHY
  每步间隔 1~10ms
  |
  V
PMIC 输出 PGOOD 信号
  |
  V
SoC 内部 POR (Power-On Reset) 释放
  |
  V
SoC Boot ROM 开始执行
  |
  V
Bootloader 初始化 DDR 和外设
  |
  V
Linux 内核启动
  |
  V
内核初始化各电源域和驱动
  |
  V
系统运行，DVFS 和 Runtime PM 动态管理功耗
```

### DVFS 调压流程

```text
调度器检测到负载变化
  |
  V
cpufreq 框架选择新的频率/电压组合
  |
  V
升频路径:
  1. 通过 I2C 写 PMIC 寄存器，升高 VDD_CORE
  2. 等待电压稳定 (PMIC PGOOD 或延时)
  3. 写时钟控制器寄存器，升高频率
  |
  V
降频路径:
  1. 写时钟控制器寄存器，降低频率
  2. 通过 I2C 写 PMIC 寄存器，降低 VDD_CORE
```

## 最小可运行示例

### 裸机低功耗模式（Cortex-M）

```c
#include <stdint.h>

#define PWR_BASE       0x40007000UL
#define PWR_CR         (*(volatile uint32_t *)(PWR_BASE + 0x00))
#define PWR_CSR        (*(volatile uint32_t *)(PWR_BASE + 0x04))

#define SCB_BASE       0xE000ED00UL
#define SCB_SCR        (*(volatile uint32_t *)(SCB_BASE + 0x10))

#define PWR_CR_LPDS    (1 << 0)
#define PWR_CR_FPDS    (1 << 9)
#define SCB_SCR_SLEEPDEEP (1 << 2)

void enter_stop_mode(void)
{
    PWR_CR |= PWR_CR_LPDS;
    SCB_SCR |= SCB_SCR_SLEEPDEEP;
    __WFI();
}

void enter_standby_mode(void)
{
    PWR_CR |= PWR_CR_FPDS | PWR_CR_LPDS;
    PWR_CR |= (1 << 3);
    SCB_SCR |= SCB_SCR_SLEEPDEEP;
    __WFI();
}

void wakeup_handler(void)
{
    if (PWR_CSR & (1 << 1)) {
        PWR_CR |= (1 << 2);
    }
}
```

### Linux Runtime PM 使用

```c
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/pm_runtime.h>

static int mydev_open(struct inode *inode, struct file *filp)
{
    struct mydev_priv *priv = container_of(filp->private_data,
                                           struct mydev_priv, miscdev);
    pm_runtime_get_sync(&priv->pdev->dev);
    return 0;
}

static int mydev_release(struct inode *inode, struct file *filp)
{
    struct mydev_priv *priv = container_of(filp->private_data,
                                           struct mydev_priv, miscdev);
    pm_runtime_put_sync(&priv->pdev->dev);
    return 0;
}

static int mydev_probe(struct platform_device *pdev)
{
    pm_runtime_enable(&pdev->dev);
    pm_runtime_set_suspended(&pdev->dev);
    return 0;
}

static int mydev_remove(struct platform_device *pdev)
{
    pm_runtime_disable(&pdev->dev);
    return 0;
}

static int mydev_runtime_suspend(struct device *dev)
{
    dev_info(dev, "runtime suspend: 关闭电源域\n");
    return 0;
}

static int mydev_runtime_resume(struct device *dev)
{
    dev_info(dev, "runtime resume: 开启电源域\n");
    return 0;
}

static const struct dev_pm_ops mydev_pm_ops = {
    SET_RUNTIME_PM_OPS(mydev_runtime_suspend,
                       mydev_runtime_resume, NULL)
};

static struct platform_driver mydev_driver = {
    .probe  = mydev_probe,
    .remove = mydev_remove,
    .driver = {
        .name = "mydev-pm",
        .pm = &mydev_pm_ops,
    },
};
module_platform_driver(mydev_driver);

MODULE_LICENSE("GPL");
```

## 代码解读

### 1. 为什么进入 Stop 模式前要配 PWR_CR

PWR_CR 控制低功耗模式的具体行为：LPDS 位决定 Stop 模式下主调压器是开（低功耗模式）还是关（深度低功耗模式）。不同配置影响唤醒速度和功耗水平。

### 2. 为什么 `pm_runtime_get_sync` 要在 open 时调用

设备在不用时可以处于挂起状态（电源域关闭）。用户空间 open 设备时调用 `pm_runtime_get_sync` 确保设备已上电，release 时调用 `pm_runtime_put_sync` 允许设备再次挂起。

### 3. 为什么设备树里 `regulator-always-on` 要谨慎使用

`regulator-always-on` 表示这个电源永远不能关闭，即使没有设备在使用。这会阻止低功耗优化。只有确实需要始终供电的域（如 DDR、RTC）才应该设这个属性。

### 4. 为什么 DVFS 升频要先升压再升频

如果先升频再升压，CPU 在电压不够时以高频运行，可能因为时序不满足而产生错误。先升压确保电压足够，再升频就安全了。

## 正确写法 vs 常见错误写法

| 场景 | 正确写法 | 常见错误写法 | 为什么错 |
| --- | --- | --- | --- |
| DVFS 升频 | 先升压 → 等稳定 → 升频 | 先升频再升压 | 电压不够时高频运行不稳定 |
| DVFS 降频 | 先降频 → 再降压 | 先降压再降频 | 电压不够时还在高频运行 |
| LDO 选型 | 压差小、电流小、低噪声 | 大压差大电流用 LDO | 效率低、发热严重 |
| DCDC 选型 | 大电流、大压差 | 小电流低噪声场景用 DCDC | 纹波大、成本高 |
| regulator-always-on | 只用于确实需要常开的域 | 所有域都设 always-on | 无法进入低功耗模式 |
| Runtime PM | 不用时 put、用时 get | 一直 get 不 put | 设备永远无法挂起 |
| 上电时序 | 按 PMIC 预设顺序 | 手动随意上电 | 可能损坏芯片 |

## 边界条件与适用范围

1. 不同 SoC 的电源域划分和电压要求差异很大，必须查数据手册。
2. LDO 的最大耗散功率受封装和环境温度限制，超出会过热保护。
3. DCDC 的电感选型影响效率和纹波，不能随意替换。
4. DVFS 的电压-频率对应关系由 SoC 厂商提供（OPP 表），不能自己猜。
5. 深度低功耗模式下 SRAM 可能丢失，唤醒后需要重新初始化。
6. 某些外设（如 USB）在低功耗模式下需要保持 PHY 供电，不能完全关闭。

## 常见坑与排查

| 现象 | 常见根因 | 优先验证方法 |
| --- | --- | --- |
| 芯片过热 | LDO 压差大电流大；散热不足 | 测输入输出电压差和电流 |
| 系统随机重启 | 供电不足；压降过大 | 示波器看电源纹波和跌落 |
| 低功耗模式进不去 | regulator-always-on；外设没关 | 查各路电源状态和驱动 PM 状态 |
| 唤醒后异常 | SRAM 丢失；外设没重新初始化 | 检查唤醒后的初始化流程 |
| DVFS 切换崩溃 | 升频时电压不够；OPP 表配错 | 查 cpufreq 日志和 PMIC 寄存器 |
| DDR 初始化失败 | 上电时序不对；电压不对 | 示波器看上电顺序和电压 |

### 推荐排查顺序

1. 先确认各电源域电压是否正确（万用表 / 示波器）。
2. 再确认上电时序是否满足手册要求。
3. 再确认 LDO/DCDC 的负载是否在额定范围内。
4. 再确认功耗异常是静态还是动态。
5. 最后检查软件的 PM 策略和设备树配置。

## 性能、稳定性、可维护性影响

1. 电源设计直接影响系统稳定性：电压不足会导致随机错误，纹波过大会导致时序问题。
2. LDO 发热可能影响周围器件，需要考虑散热和布局。
3. 不合理的 always-on 配置会显著增加功耗，缩短电池寿命。
4. DVFS 策略影响性能和功耗的平衡，需要根据场景调优。
5. 良好的电源域划分和 PM 策略能显著降低系统功耗，提高可靠性。

## 面试 / 问答怎么讲

### 30 秒版本

SoC 有多个电源域因为不同模块需要不同电压。LDO 线性稳压简单但效率低，DCDC 开关稳压效率高但纹波大。动态功耗跟电压平方和频率成正比，所以降电压比降频率更有效。DVFS 根据负载动态调整电压和频率来省电。

### 3 分钟版本

从电源域划分讲起：核心域低压省电、IO 域由接口标准决定、模拟域需要干净电源。然后讲 LDO 和 DCDC 的区别：LDO 简单低噪声但效率低，DCDC 高效但需要电感有纹波。再讲功耗来源：静态功耗来自漏电流，动态功耗 P=αCV²f。最后讲 DVFS 和低功耗模式：降电压最有效，WFI/Stop/Standby 逐级降低功耗。

### 10 分钟版本

可以系统展开：先讲电源域划分的原因和典型配置，再详细对比 LDO 和 DCDC 的工作原理和选型，再讲 PMIC 的架构和控制方式。然后从公式 P=αCV²f 出发，分析功耗来源和优化策略。再讲 DVFS 的实现：OPP 表、cpufreq 框架、调压顺序。再讲 Linux 的 genpd 和 runtime PM 框架。最后讲上电时序和排障方法。

## 实战练习

1. 在原理图上找出 SoC 的所有电源域，确认每个域的电压值和供电来源（LDO/DCDC）。
2. 计算一个 LDO 的耗散功率：Vin=5V, Vout=3.3V, Iload=500mA，判断是否需要散热片。
3. 在 Linux 系统上用 `cat /sys/kernel/debug/pm_genpd/pm_genpd_summary` 查看各电源域状态。
4. 修改设备树，把一个不必要的 `regulator-always-on` 去掉，观察功耗变化。
5. 用示波器测量 PMIC 的上电时序，确认是否符合 SoC 手册要求。

## 关键要点

1. SoC 多电源域是因为不同模块需要不同电压和供电策略。
2. LDO 线性稳压低噪声但效率低，DCDC 开关稳压高效但有纹波。
3. PMIC 集成多路 LDO/DCDC，通过 I2C 控制，管理上电时序。
4. 动态功耗 P=αCV²f，降电压效果最显著（二次方关系）。
5. DVFS 升频先升压再升频，降频先降频再降压。
6. 低功耗模式逐级关闭更多模块，从 WFI 到 Standby 功耗递减。
7. 上电时序必须满足 SoC 手册要求，否则可能不稳定或损坏。
