# 硬件-调试工具与测量方法

## 原始问题

示波器、逻辑分析仪、万用表分别用来测什么？探头怎么选？测量时有哪些常见错误？怎么用工具验证硬件问题？波形怎么看？什么时候该用什么工具？

## 先给结论

调试工具的核心是"不同工具看不同层面的信号"：

1. 万用表看静态值：电压、电流、电阻、通断，是排障的第一步。
2. 示波器看动态波形：电压随时间的变化，是信号调试的核心工具。
3. 逻辑分析仪看数字协议：多个通道同时采集，解析 I2C/SPI/UART 协议，是通信调试的利器。
4. 探头和测量方法直接影响结果，错误的测量方式会给出误导性数据。
5. 选对工具、用对方法，才能把"感觉有问题"变成"确认问题在哪"。

如果只知道"万用表量电压、示波器看波形"，但讲不清什么时候用哪个、探头怎么选、怎么避免测量误差，就还没有真正掌握调试工具与测量方法。

## 这个知识解决什么问题

这篇笔记主要解决下面几类问题：

1. 不知道什么时候该用万用表、什么时候该用示波器、什么时候该用逻辑分析仪。
2. 示波器探头不会选，测出来的波形跟实际不符。
3. 不知道怎么用工具验证"供电正常""信号正常""时序正确"。
4. 面试时被问"怎么确认 I2C 通信是否正常"，只会说"看日志"。
5. 测量结果跟预期不符，不知道是测量方法有问题还是硬件有问题。

它在 AI 时代依然重要，因为 AI 能帮你分析代码和日志，但当问题出在物理层时，AI 无法帮你测量电压、看波形、抓协议。掌握调试工具后，你才能在"软件层面找不到问题"时，回到物理层验证。

## 核心概念 / 本质机制

### 1. 万用表

万用表是最基础但最常用的测量工具：

| 测量模式 | 用途 | 精度 |
| --- | --- | --- |
| DC 电压 | 测量电源电压、IO 电平 | ±0.5% |
| AC 电压 | 测量交流电压 | ±1% |
| DC 电流 | 测量功耗、漏电流 | ±1% |
| 电阻 | 测量上拉下拉电阻、通断 | ±0.5% |
| 通断 | 快速检查连接是否导通 | 蜂鸣器 |
| 二极管 | 测量二极管压降、判断方向 | ±1% |

万用表的使用场景：

1. **确认供电**：量 VDD 引脚电压是否在规格范围内。
2. **确认电平**：量 GPIO 输出高/低电平是否达标。
3. **确认通断**：检查走线、焊点、连接器是否连通。
4. **确认上下拉**：量电阻值是否正确。
5. **确认短路**：量 VDD 和 GND 之间是否短路。

万用表的局限性：

1. 只能测直流或低频交流，看不到信号变化过程。
2. 输入阻抗有限（通常 10MΩ），测量高阻抗节点时可能影响电路。
3. 电流档需要串联进电路，不方便。

### 2. 示波器

示波器是观察电压随时间变化的核心工具：

#### 关键参数

| 参数 | 含义 | 典型值 |
| --- | --- | --- |
| 带宽 | 能准确测量的最高信号频率 | 50MHz~8GHz |
| 采样率 | 每秒采集的点数 | 1GSa/s~40GSa/s |
| 通道数 | 同时测量的信号路数 | 2~8 |
| 存储深度 | 能存储的采样点数 | 1M~800M 点 |
| 上升时间 | 能分辨的最快边沿 | 3.5ns (100MHz) ~ 43ps (8GHz) |

带宽选择经验：

```text
示波器带宽 ≥ 3~5 × 被测信号最高频率分量

常见场景:
  UART (115200bps):    50MHz 足够
  SPI (25MHz):         100MHz
  SPI (50MHz):         200MHz
  DDR3 (800MHz):       1GHz+
  USB 3.0 (5Gbps):     2GHz+
```

#### 示波器的触发模式

| 触发模式 | 用途 |
| --- | --- |
| 边沿触发 | 最常用，信号上升/下降过阈值时触发 |
| 脉宽触发 | 捕获特定宽度的脉冲 |
| 超时触发 | 捕获信号长时间不变的情况 |
| 欠幅脉冲 | 捕获幅度不够的脉冲 |
| 视频触发 | 分离视频同步信号 |
| 协议触发 | I2C/SPI/UART 特定帧触发 |

#### 示波器的测量功能

| 测量项 | 含义 |
| --- | --- |
| 频率 | 信号周期频率 |
| 占空比 | 高电平占周期的比例 |
| 上升时间 | 信号从 10% 到 90% 的时间 |
| 下降时间 | 信号从 90% 到 10% 的时间 |
| 最大值/最小值 | 信号的峰值 |
| 峰峰值 | 最大值减最小值 |
| RMS | 有效值 |
| 过冲 | 信号超过稳态值的量 |

### 3. 示波器探头

探头的选择和使用直接影响测量准确性：

#### 探头类型

| 探头类型 | 用途 | 负载效应 |
| --- | --- | --- |
| 无源探头 (10:1) | 通用测量 | 10MΩ // 8~15pF |
| 无源探头 (1:1) | 低幅信号 | 1MΩ // 50~100pF |
| 有源探头 | 高频信号 | 1MΩ // < 1pF |
| 差分探头 | 差分信号 | 高阻抗 // 低电容 |
| 电流探头 | 测量电流 | 不接触电路 |

#### 10:1 无源探头

最常用的探头，衰减 10 倍：

```text
优点:
  输入阻抗高 (10MΩ)，对电路影响小
  输入电容小 (8~15pF)，适合中频信号
  耐压高 (通常 300V+)

缺点:
  信号衰减 10 倍，小信号可能看不清
  需要补偿调节

补偿调节:
  探头钩到示波器的校准信号 (通常 1kHz 方波)
  调节探头上的补偿螺丝
  直到方波边沿平直无过冲/圆角
```

#### 探头的负载效应

探头接入电路后会改变被测信号：

```text
探头的等效电路:
  10MΩ 电阻 // 10pF 电容

对直流信号: 10MΩ 并联，影响很小
对高频信号: 10pF 电容的阻抗随频率降低

  1MHz 时: Zc = 1/(2π×1M×10pF) ≈ 16kΩ
  10MHz 时: Zc ≈ 1.6kΩ
  100MHz 时: Zc ≈ 160Ω

高频时探头的电容负载效应很显著！
```

### 4. 逻辑分析仪

逻辑分析仪专注于数字信号的协议分析：

#### 关键参数

| 参数 | 含义 | 典型值 |
| --- | --- | --- |
| 通道数 | 同时采集的信号路数 | 8~136 |
| 采样率 | 每秒采样点数 | 100MSa/s~6GSa/s |
| 存储深度 | 能存储的采样点数 | 1M~1G 点 |
| 协议支持 | 能解析的协议种类 | I2C/SPI/UART/CAN/... |

#### 逻辑分析仪 vs 示波器

| 对比项 | 逻辑分析仪 | 示波器 |
| --- | --- | --- |
| 信号类型 | 只看数字（0/1） | 看模拟波形 |
| 通道数 | 多（8~136） | 少（2~8） |
| 协议解析 | 强（自动解码） | 弱（部分支持） |
| 信号质量 | 看不到模拟细节 | 能看振铃/过冲 |
| 定时精度 | 高（多通道对齐） | 中 |
| 适用场景 | 协议调试、时序关系 | 信号质量、模拟问题 |

#### 逻辑分析仪的使用场景

1. **I2C 调试**：抓取 SDA/SCL 波形，自动解析地址、数据、ACK/NACK。
2. **SPI 调试**：抓取 CLK/MOSI/MISO/CS，自动解析数据帧。
3. **UART 调试**：抓取 TX/RX，自动解析波特率和数据。
4. **时序关系**：看多个信号之间的时序关系（如 CS 低到第一个 CLK 的延迟）。
5. **协议异常**：捕获通信中的异常帧（如 I2C 的 NACK、重复 START）。

### 5. 测量方法与常见错误

#### 测量电源纹波

```text
正确方法:
1. 示波器设为 AC 耦合（滤掉直流分量，只看纹波）
2. 探头用 10:1（减少负载效应）
3. 探头地线尽量短（用弹簧接地夹，不用鳄鱼夹）
4. 探头直接点到芯片电源引脚（不是 PCB 边缘的测试点）
5. 时基设为 1~10μs/div
6. 读取峰峰值

常见错误:
✗ 用 DC 耦合看纹波 → 直流分量太大，纹波显示不清楚
✗ 探头地线太长 → 地线电感引入噪声，纹波读数偏大
✗ 量 PCB 边缘而不是芯片引脚 → 走线压降导致读数偏小
```

#### 测量信号边沿

```text
正确方法:
1. 示波器设为 DC 耦合
2. 时基设为 10~100ns/div
3. 触发设为边沿触发
4. 测量上升时间和过冲

常见错误:
✗ 探头没补偿 → 边沿波形失真
✗ 采样率不够 → 边沿被欠采样，上升时间读数偏大
✗ 用 1:1 探头测高速信号 → 电容负载太大，改变信号
```

#### 测量 I2C 通信

```text
方法一: 逻辑分析仪
1. 通道接 SDA 和 SCL
2. 设置 I2C 协议解析
3. 设置触发条件（如特定地址或 START 条件）
4. 查看解析后的地址和数据

方法二: 示波器
1. 两个通道分别接 SDA 和 SCL
2. 触发设为 SCL 边沿
3. 手动对照 I2C 协议读地址和数据
4. 能同时看到信号质量（振铃、过冲等）

推荐: 先用逻辑分析仪确认协议内容，再用示波器检查信号质量
```

#### 测量功耗

```text
方法一: 万用表串联
1. 断开电源正极
2. 万用表设为电流档
3. 串联进电源路径
4. 读取电流值
缺点: 只能量平均电流，看不到瞬态变化

方法二: 电流探头 + 示波器
1. 电流探头夹在电源线上
2. 示波器观察电流波形
3. 能看到瞬态电流变化
缺点: 设备贵，精度有限

方法三: 采样电阻 + 示波器
1. 在电源路径中串联一个小电阻 (0.1~1Ω)
2. 示波器差分探头量电阻两端电压
3. I = V / R
优点: 便宜，能看到瞬态
```

### 6. 测量接地技巧

接地方式对测量结果影响很大：

```text
方式一: 探头接地夹 + 鳄鱼夹
  地线长度: 10~20cm
  地线电感: 50~100nH
  适用: 低频信号 (< 1MHz)
  问题: 高频时地线电感引入振铃

方式二: 弹簧接地夹 (推荐)
  地线长度: < 1cm
  地线电感: < 5nH
  适用: 中频信号 (< 100MHz)
  优点: 地线短，引入噪声小

方式三: 同轴接地 (BNC 直连)
  地线长度: 0
  适用: 高频信号
  优点: 最小化地线电感
```

### 7. 工具选择决策

```text
问题类型 → 推荐工具

供电是否正常？         → 万用表 (量电压)
信号电平是否达标？     → 万用表 (量静态电平)
信号波形是否正常？     → 示波器 (看动态波形)
通信协议是否正确？     → 逻辑分析仪 (解析协议)
通信时序是否满足？     → 逻辑分析仪 (多通道对齐)
信号质量是否合格？     → 示波器 (看振铃/过冲/眼图)
功耗是否正常？         → 万用表 (量电流) 或 电流探头
走线是否连通？         → 万用表 (通断档)
EMI 是否超标？         → 近场探头 + 频谱仪
```

## 最小可运行示例

### 用示波器验证 GPIO 输出

```c
/* 在代码中翻转 GPIO，用示波器验证 */

#include <linux/gpio/consumer.h>

static void debug_gpio_toggle(struct gpio_desc *gpio)
{
    int i;

    for (i = 0; i < 100; i++) {
        gpiod_set_value(gpio, 1);
        ndelay(500);
        gpiod_set_value(gpio, 0);
        ndelay(500);
    }
}

/* 示波器设置:
 * - 通道接 GPIO 引脚
 * - 触发: 边沿触发, 阈值 VDD/2
 * - 时基: 200ns/div
 * - 观察项目:
 *   1. 高电平是否达到 VDD - 0.4V
 *   2. 低电平是否低于 0.4V
 *   3. 上升时间是否合理
 *   4. 有无振铃或过冲
 */
```

### 用逻辑分析仪抓 I2C 通信

```c
/* 触发 I2C 通信，用逻辑分析仪抓取 */

#include <linux/i2c.h>

static int test_i2c_communication(struct i2c_client *client)
{
    u8 reg = 0x00;
    u8 val;
    int ret;

    ret = i2c_smbus_read_byte_data(client, reg);
    if (ret < 0) {
        dev_err(&client->dev, "I2C 读失败: %d\n", ret);
        return ret;
    }
    val = ret;
    dev_info(&client->dev, "REG[0x%02x] = 0x%02x\n", reg, val);

    return 0;
}

/* 逻辑分析仪设置:
 * - 通道 0: SDA
 * - 通道 1: SCL
 * - 协议: I2C, 7-bit 地址
 * - 触发: START 条件
 * - 观察项目:
 *   1. 地址是否正确
 *   2. 是否收到 ACK
 *   3. 数据是否正确
 *   4. 时序是否符合 I2C 规范
 */
```

```text
5. 偏差 > 5% 需要进一步排查
```

## 代码解读

### 1. 为什么 GPIO 翻转测试要用 ndelay 而不是 msleep

ndelay 是纳秒级延迟，产生的高频方波适合示波器观察信号边沿质量。msleep 是毫秒级，频率太低看不到边沿细节。但注意 ndelay 在非实时系统中精度有限，实际延迟可能更长。

### 2. 为什么 I2C 测试用 i2c_smbus_read_byte_data

这是最简单的 I2C 读取操作：写 1 字节寄存器地址，读 1 字节数据。逻辑分析仪能清楚看到 START → 地址 → ACK → 寄存器号 → ACK → RESTART → 地址 → ACK → 数据 → NACK → STOP 的完整流程。

### 3. 为什么量电压要在芯片引脚而不是 PCB 边缘

PCB 走线有电阻和电感，大电流时走线上有压降。芯片引脚处的电压才是芯片实际看到的电压。如果在 PCB 边缘量，走线压降可能让你误以为电压够，但芯片端实际不够。

## 正确写法 vs 常见错误写法

| 场景 | 正确做法 | 常见错误 | 为什么错 |
| --- | --- | --- | --- |
| 测纹波 | AC 耦合 + 短地线 + 芯片引脚 | DC 耦合 + 长地线 + PCB 边缘 | 看不清纹波或引入噪声 |
| 测高速信号 | 10:1 探头 + 补偿调节 | 1:1 探头 | 电容负载太大改变信号 |
| 抓 I2C | 逻辑分析仪 + 协议解析 | 示波器手动读 | 效率低容易出错 |
| 量供电 | 芯片引脚 | PCB 边缘 | 走线压降导致读数偏小 |
| 量电流 | 串联万用表或电流探头 | 并联万用表 | 短路危险 |
| 探头接地 | 弹簧接地夹 | 长鳄鱼夹地线 | 高频时地线电感引入噪声 |
| 示波器带宽 | ≥ 3~5× 信号频率 | 带宽不够 | 信号失真 |

## 边界条件与适用范围

1. 这篇笔记面向软件工程师的测量入门，不是专业测试工程师课程。
2. 低端示波器（50MHz 以下）适合 MCU 和低速外设调试，高速接口需要更高端设备。
3. 逻辑分析仪的采样率必须 ≥ 4× 信号频率，否则可能漏采。
4. 电流探头的精度通常不如万用表，适合看趋势不适合精确测量。
5. 某些测量需要特殊设备（频谱仪、TDR、近场探头），不在本篇范围。

## 常见坑与排查

| 现象 | 常见测量问题 | 优先验证方法 |
| --- | --- | --- |
| 纹波读数异常大 | 探头地线太长 | 换弹簧接地夹 |
| 信号边沿有振铃 | 探头没补偿 | 调补偿螺丝 |
| 信号幅度偏小 | 用了 1:1 探头但示波器设了 10:1 | 检查探头衰减比设置 |
| 逻辑分析仪数据错 | 采样率不够 | 提高采样率 |
| 量电压偏低 | 量了 PCB 边缘 | 改量芯片引脚 |
| I2C 解析乱码 | 通道接反或阈值设错 | 检查接线和阈值 |

### 推荐排查顺序

1. 先确认测量工具设置是否正确（耦合方式、衰减比、触发条件）。
2. 再确认探头是否补偿好。
3. 再确认接地方式是否合理。
4. 再确认测量点是否正确（芯片引脚 vs PCB 边缘）。
5. 最后才怀疑硬件本身有问题。

## 性能、稳定性、可维护性影响

1. 正确使用调试工具能快速定位问题，减少"猜问题"的时间。
2. 错误的测量方法会给出误导性数据，导致在错误方向上浪费时间。
3. 探头负载效应可能改变被测信号，测量结果不代表真实工作状态。
4. 保留测量记录和波形截图，方便后续复盘和对比。
5. 掌握多种工具的组合使用，比只会用一种工具效率高得多。

## 面试 / 问答怎么讲

### 30 秒版本

万用表量静态电压和通断，示波器看动态波形和信号质量，逻辑分析仪抓数字协议和时序。测量时要注意探头选择、接地方式和测量点位置，错误的测量方法会给出误导性数据。

### 3 分钟版本

从三种工具的定位讲起：万用表看静态值（供电、电平、通断），示波器看动态波形（边沿、振铃、纹波），逻辑分析仪看协议（I2C/SPI/UART 解析）。然后讲示波器探头：10:1 无源探头最常用，必须做补偿调节，接地线要短。再讲常见测量方法：纹波用 AC 耦合+短地线，信号边沿用 DC 耦合+高采样率。最后讲工具选择：供电问题用万用表，信号质量用示波器，协议问题用逻辑分析仪。

### 10 分钟版本

可以系统展开：先详细讲三种工具的原理和参数。然后讲示波器探头的等效电路和负载效应，用公式说明探头电容在高频时的影响。再讲各种测量方法的正确做法和常见错误。再讲逻辑分析仪的协议解析功能和触发设置。再讲功耗测量的三种方法。最后讲调试时的工具组合策略和测量记录的重要性。

## 实战练习

1. 用万用表测量开发板上所有电源域的电压，记录并跟手册对比。
2. 用示波器观察一个 GPIO 翻转的波形，测量上升时间和过冲。
3. 用示波器测量一个 LDO 输出的纹波，对比长地线和短地线的测量差异。
4. 用逻辑分析仪抓取一次 I2C 通信，解析出地址和数据。
5. 用万用表通断档追踪一个信号从 SoC 到外设的完整路径。

## 关键要点

1. 万用表看静态值（电压、电流、通断），是排障第一步。
2. 示波器看动态波形，是信号调试的核心工具。
3. 逻辑分析仪看数字协议和时序，是通信调试的利器。
4. 10:1 无源探头最常用，必须做补偿调节，接地线要短。
5. 测纹波用 AC 耦合 + 短地线 + 芯片引脚。
6. 探头有负载效应，高频时电容负载会改变被测信号。
7. 选对工具、用对方法，才能得到可靠的测量结果。
