# 外设-RTC基础

## 原始问题

RTC 到底是什么？为什么它看起来只是“保存时间”，但项目里常见时间漂移、断电丢时、闹钟不准、时区和夏令时处理混乱、日志时间错乱这些问题？应该怎样系统掌握 RTC，而不是只会 set/get 时间接口？

## 先给结论

RTC 的本质是“在低功耗时基上持续维护系统日历时间和定时事件”，它不是普通软件计时器，而是跨休眠、跨复位场景的时间基准。

先记住下面几个结论：

1. RTC 价值在于低功耗持续计时和掉电后时间保持能力。
2. RTC 准确性高度依赖时钟源（LSE/LSI）和校准策略。
3. RTC 时间正确不等于业务时间正确，时区与同步策略要单独设计。
4. 闹钟、周期唤醒、时间戳记录是 RTC 常见工程用途。
5. 排障要分层：时钟源稳定性 -> RTC 配置 -> 时间同步 -> 上层时间语义。

## 这个知识解决什么问题

1. 设备休眠唤醒后时间错乱。
2. 长时间运行后时间累计偏差明显。
3. 日志排序混乱，无法可信追溯。

## 核心概念 / 本质机制

### 1. RTC 与系统 tick 的区别

1. 系统 tick 依赖主系统运行，休眠或复位会中断。
2. RTC 依赖低功耗时钟，可跨低功耗持续走时。

### 2. 常见 RTC 时钟源

1. LSE（外部 32.768kHz 晶振）：精度较好，常用于高可靠时间维护。
2. LSI（内部 RC）：成本低，但漂移通常更大。

### 3. 日历计时与时间戳

RTC 常提供：

1. 年月日时分秒。
2. 亚秒计数（部分芯片）。
3. 闹钟和唤醒定时器。

### 4. 校准与同步

工程常见时间体系：

1. RTC 维护本地基准时间。
2. 上线后通过 GNSS/NTP/主站定期校时。
3. 记录最近校时来源与偏移。

### 5. 断电保持

RTC 通常依赖备份域供电（电池/超级电容）。

若备份域异常，常见现象是每次上电时间回默认值。

## 数据流 / 控制流 / 时序关系

```text
上电初始化
-> 检查备份域与RTC有效标志
-> 无效则首次设时
-> 周期读取RTC生成时间戳
-> 业务日志/调度使用时间戳
-> 外部时间源到来时执行校时
```

## 最小可运行示例

```c
#define RTC_BASE            0x40002800
#define RTC_TR              (*(volatile unsigned int *)(RTC_BASE + 0x00))
#define RTC_DR              (*(volatile unsigned int *)(RTC_BASE + 0x04))
#define RTC_CR              (*(volatile unsigned int *)(RTC_BASE + 0x08))

static void rtc_init(void)
{
    /* 示例：真实工程需补时钟源、备份域解锁、预分频配置 */
    RTC_CR |= 1U;
}

static unsigned int rtc_get_time_raw(void)
{
    return RTC_TR;
}
```

## 正确写法 vs 常见错误写法

| 场景 | 正确写法 | 常见错误写法 | 为什么错 |
| --- | --- | --- | --- |
| 首次设时 | 通过有效标志区分首次启动 | 每次上电都重置时间 | 时间无法连续 |
| 时间语义 | 内部统一 UTC 或统一本地规则 | 各模块各自处理时区 | 日志与调度混乱 |
| 精度管理 | 定期校时并记录偏移 | 长期依赖未校准 RC 时钟 | 漂移累积明显 |

## 常见坑与排查

1. 时间每次上电归零：先查备份域供电与有效标志。
2. 一天偏差明显：查时钟源精度与校准策略。
3. 闹钟偶发不触发：查唤醒源冲突与低功耗切换时序。

## 工程落地建议

1. 定义统一时间基准（推荐内部 UTC）。
2. 启动早期记录 RTC 有效性与复位原因。
3. 校时动作做幂等和限幅，避免时间大跳变影响业务。

## 关键要点

1. RTC 是跨低功耗和复位的时间基准。
2. 时钟源与校准策略决定长期准确性。
3. 时间语义设计和同步策略同样关键。
