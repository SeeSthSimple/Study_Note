# 外设-定时器与PWM基础

## 原始问题

定时器和 PWM 为什么在嵌入式里几乎无处不在？看起来只是“计数”和“输出波形”，但真正做项目时却总会遇到定时不准、占空比不对、抖动、更新时突变、外设联动异常。应该怎样系统掌握定时器与 PWM，而不是只会调一个初始化函数？

## 先给结论

定时器的本质是“按固定时基进行计数并在关键时刻触发动作”，PWM 的本质是“利用定时器比较机制输出可控占空比的周期波形”。

先记住下面几个结论：

1. 定时器最核心能力是：计时、比较、捕获、触发。
2. PWM 不是独立外设魔法，通常是定时器的一个工作模式。
3. PWM 频率由时钟、预分频、计数周期共同决定；占空比由比较值决定。
4. 工程里“看起来是 PWM 问题”，根因常在时钟树、计数模式、更新时机、引脚复用和负载电路。
5. 学定时器与 PWM 的关键，不是背寄存器名，而是建立“时钟 -> 计数 -> 比较 -> 输出”的完整链路。

如果只能背“PWM 占空比 50% 就是亮一半”，却讲不清为什么调频率会影响分辨率、为什么改比较值会出现毛刺、为什么同一个定时器多通道会相互约束，就说明这部分还没有真正掌握。

## 这个知识解决什么问题

这篇笔记主要解决下面几类问题：

1. 刚接触定时器时，不清楚 PSC/ARR/CCR 这些配置项到底控制了什么。
2. PWM 明明配置了，但频率不对、占空比异常、输出没波形，不知道先查哪层。
3. 做 LED 调光、电机调速、蜂鸣器驱动、周期任务调度时，缺少统一思路。
4. 面试时会背“PWM 是脉宽调制”，但讲不清定时器内部计数和比较机制。

它在 AI 时代仍然重要，因为 AI 可以生成一段看似标准的定时器初始化代码，但它不知道你的系统时钟是否变更、引脚是否切到复用功能、负载是否需要互补输出和死区，也不知道你是要“改频率不改占空比”还是“改占空比不改频率”。理解越扎实，越能判断 AI 代码是“能编译”，还是“上板就翻车”。

## 核心概念 / 本质机制

### 1. 定时器到底在做什么

定时器本质上是在时钟驱动下不断计数。

典型流程是：

1. 输入时钟进入定时器。
2. 经过预分频后得到计数时钟。
3. 计数器按计数时钟递增或递减。
4. 到达设定阈值时触发更新、比较、中断或输出动作。

所以定时器不是“等一会儿再干活”，而是“以硬件计数为核心的时序控制器”。

### 2. PWM 如何由定时器生成

最常见 PWM 生成方式是“计数器 + 比较寄存器”。

以向上计数为例：

1. 计数器从 0 计到 ARR（自动重装值）。
2. 当计数值小于 CCR（比较值）时输出高电平。
3. 当计数值大于等于 CCR 时输出低电平。
4. 计数到 ARR 后回到 0，进入下一个周期。

因此：

- 周期由 ARR（以及预分频）决定。
- 占空比由 CCR/ARR 比值决定。

### 3. 频率和占空比怎么计算

典型向上计数 PWM 下：

1. `f_timer = f_clk / (PSC + 1)`
2. `f_pwm = f_timer / (ARR + 1)`
3. `duty = CCR / (ARR + 1)`

这三条公式是最常用主线。

高频误区：

1. 只改 ARR 不改 CCR，结果占空比比例被改变。
2. 想提高频率又保持高分辨率，但 ARR 变小后占空比步进变粗。
3. 忘了时钟树变化，导致同样寄存器配置在不同板卡上频率不同。

### 4. 预装载和更新事件为什么重要

很多定时器支持预装载（preload）。

意义是：

1. 软件先把新 CCR/ARR 写入缓冲寄存器。
2. 等到更新事件（通常周期边界）再一次性生效。

这样做可以避免周期中途改值导致波形毛刺。

如果关闭预装载，运行中直接改比较值，可能出现：

1. 某个周期脉宽突变。
2. 输出短暂异常脉冲。
3. 多通道同步性变差。

### 5. 边沿对齐和中心对齐

常见 PWM 计数模式：

1. 边沿对齐：计数器单向计数（常见、实现简单）。
2. 中心对齐：计数器上下往返计数（谐波特性更好，常用于电机控制）。

中心对齐的代价通常是：

1. 频率计算方式要重新确认。
2. 可用更新时机更复杂。

### 6. 定时器不只做 PWM

定时器常见功能还包括：

1. 基本定时中断（周期任务节拍）。
2. 输入捕获（测频率、测脉宽）。
3. 输出比较（按时刻翻转/置位输出）。
4. 单脉冲模式。
5. 主从触发联动（触发 ADC、触发其他定时器）。

把这些串起来，才能理解它为什么是很多外设协同的“时序中枢”。

### 7. 引脚复用和输出使能是常见硬门槛

PWM 波形要真正出现在引脚上，通常同时需要：

1. 定时器内部 PWM 模式配置正确。
2. 通道输出使能。
3. GPIO 切到对应复用功能（AF/pinmux）。
4. 某些高级定时器还要总输出使能位（例如 MOE）打开。

很多“寄存器看着都对但引脚没波形”的问题，根因在这条链上漏了一环。

## 数据流 / 控制流 / 时序关系

下面用“PWM 调光 LED”串一条最小主线：

```text
系统时钟
-> 定时器预分频得到计数时钟
-> 计数器周期运行（0 到 ARR）
-> 计数值与 CCR 比较
-> 定时器通道输出高低电平波形
-> GPIO 复用引脚输出 PWM
-> LED 因占空比变化呈现亮度变化
```

这条链上每一步都可能出问题：

1. 时钟源和预分频配置不对，频率全错。
2. ARR/CCR 计算错，占空比异常。
3. GPIO 没切复用，示波器看不到波形。
4. 输出极性设反，逻辑亮灭颠倒。
5. 运行时直接改寄存器，亮度变化抖动或突变。

## 最小可运行示例

下面给一个简化的寄存器级示例，目标：

1. 配置定时器输出 1kHz PWM。
2. 通过修改占空比实现亮度变化。

```c
#define TIM_BASE          0x40000000
#define TIM_PSC           (*(volatile unsigned int *)(TIM_BASE + 0x00))
#define TIM_ARR           (*(volatile unsigned int *)(TIM_BASE + 0x04))
#define TIM_CCR1          (*(volatile unsigned int *)(TIM_BASE + 0x08))
#define TIM_CNT           (*(volatile unsigned int *)(TIM_BASE + 0x0C))
#define TIM_CR            (*(volatile unsigned int *)(TIM_BASE + 0x10))
#define TIM_CCER          (*(volatile unsigned int *)(TIM_BASE + 0x14))
#define TIM_CCMR1         (*(volatile unsigned int *)(TIM_BASE + 0x18))
#define TIM_EGR           (*(volatile unsigned int *)(TIM_BASE + 0x1C))

#define TIM_CR_CEN        (1U << 0)
#define TIM_CCER_CC1E     (1U << 0)
#define TIM_EGR_UG        (1U << 0)

static void pwm_init(void)
{
    /* 假设定时器输入时钟 72MHz，目标 PWM 1kHz */
    TIM_PSC = 71;          /* 72MHz / (71 + 1) = 1MHz */
    TIM_ARR = 999;         /* 1MHz / (999 + 1) = 1kHz */

    /* 通道1 PWM 模式1，具体位定义按芯片手册调整 */
    TIM_CCMR1 = (6U << 4);

    TIM_CCR1 = 500;        /* 初始 50% 占空比 */
    TIM_CCER |= TIM_CCER_CC1E;

    TIM_EGR |= TIM_EGR_UG; /* 产生更新事件，装载预分频和周期 */
    TIM_CR |= TIM_CR_CEN;  /* 启动计数器 */
}

static void pwm_set_duty(unsigned int permille)
{
    if (permille > 1000)
        permille = 1000;

    TIM_CCR1 = (TIM_ARR + 1) * permille / 1000;
}

int main(void)
{
    unsigned int duty = 0;
    int step = 1;

    pwm_init();

    while (1) {
        pwm_set_duty(duty);

        if (step)
            duty += 10;
        else
            duty -= 10;

        if (duty >= 1000)
            step = 0;
        else if (duty == 0)
            step = 1;

        for (volatile unsigned int i = 0; i < 80000; i++)
            ;
    }
}
```

这个示例里假设：

1. 对应 GPIO 已经提前配置为定时器复用输出。
2. LED 对 PWM 频率和极性匹配。
3. 芯片手册中的 PWM 模式位定义与示例一致。

如果你的板子是低电平点亮、定时器时钟不是 72MHz，或者通道映射不同，参数都要按实际硬件改。

## 代码解读

### 1. 为什么先定频再调占空比

工程里一般先固定 PWM 频率，再动态改 CCR 调占空比。

这样做能让“亮度控制”“电机转速控制”等逻辑稳定，不会因频率联动引入额外变量。

### 2. 为什么占空比建议用千分比接口

示例用 `permille`（0~1000）而不是直接写 CCR。

这样上层业务不关心 ARR 细节，移植到不同频率配置时改动更小。

### 3. 为什么要触发更新事件

`TIM_EGR |= TIM_EGR_UG` 的作用是尽快把预分频、周期等配置装载到生效寄存器。

少这一步时，常见现象是“寄存器写了，但输出行为延后或不符合预期”。

### 4. 为什么这个示例仍是最小闭环

真实项目里通常还要补：

1. 时钟树初始化和定时器时钟使能。
2. GPIO 复用初始化。
3. 预装载开关和同步更新策略。
4. 中断/DMA 联动更新占空比。
5. 死区、互补输出、刹车输入（电机场景）。

## 正确写法 vs 常见错误写法

| 场景 | 正确写法 | 常见错误写法 | 为什么错 |
| --- | --- | --- | --- |
| 频率设计 | 先确认时钟源，再算 PSC/ARR | 直接抄示例值 | 时钟不同会导致频率全偏 |
| 占空比控制 | 用 CCR 与 ARR 比例计算 | 把 CCR 当固定绝对值写死 | 改频率后占空比会失真 |
| 输出可见性 | 同时检查定时器配置和 pinmux | 只看定时器寄存器 | 引脚复用不对就无波形 |
| 运行时更新 | 用预装载+更新事件控制生效点 | 周期中途随意改关键寄存器 | 可能出现毛刺和突变 |
| 多通道同步 | 统一更新时机 | 各通道分散写寄存器 | 相位关系可能漂移 |
| 排障入口 | 示波器先看真实波形 | 只看串口打印日志 | 时序问题日志看不出来 |

## 边界条件与适用范围

1. 这篇笔记面向 MCU/SoC 常见通用定时器与 PWM 基础，不绑定具体厂商寄存器细节。
2. 不同芯片在高级定时器功能、时钟倍率、死区控制、触发矩阵上差异很大，不能直接照搬地址和位定义。
3. PWM 适合控制平均功率类场景（调光、调速、加热），不等于真正模拟电压输出。
4. 遇到高精度低噪声模拟输出需求，通常要转 DAC 或外部滤波与闭环控制方案。

## 常见坑与排查

| 现象 | 常见根因 | 优先验证方法 |
| --- | --- | --- |
| 没有 PWM 波形 | GPIO 未复用；通道未使能；主输出没开 | 查 pinmux、输出使能位、示波器看引脚 |
| 频率不对 | 时钟树理解错；PSC/ARR 计算错 | 读时钟配置、反算实际频率 |
| 占空比不对 | CCR 计算错；极性反了 | 示波器测高电平宽度和周期 |
| 运行中偶发毛刺 | 更新时机不对；未启用预装载 | 查更新事件和 preload 配置 |
| 多路 PWM 不同步 | 写寄存器时序分散；定时器不同步启动 | 用同步触发或统一更新 |
| LED 调光有闪烁 | PWM 频率过低 | 提高频率并评估分辨率 |
| 电机啸叫严重 | 频率落在可闻区；驱动策略不匹配 | 调整 PWM 频率和控制策略 |

### 推荐排查顺序

1. 先确认引脚复用、通道使能、时钟使能是否完整。
2. 再确认频率计算链：时钟源 -> PSC -> ARR。
3. 再测实际波形：周期、脉宽、极性是否符合预期。
4. 再看运行时更新策略是否导致毛刺。
5. 最后再看负载侧问题（驱动器、电源、布线、电磁干扰）。

### 常用验证方式

1. 示波器测周期和占空比。
2. 逻辑分析仪看多通道同步关系。
3. 读回关键寄存器确认配置是否生效。
4. 先断开负载看空载波形，再挂载验证。
5. 配合电流探头观察负载响应（电机/功率场景）。

## 工程落地建议

### 1. 用“频率”和“占空比”两个抽象接口对外

上层业务尽量不要直接操作寄存器，而是通过统一接口表达意图。

这样做的好处是：从一个芯片迁移到另一个芯片时，业务层基本不改。

### 2. 先确定频率区间，再谈分辨率

PWM 设计通常是个折中：

1. 频率太低，会闪烁或啸叫。
2. 频率太高，ARR 变小，占空比分辨率下降。

先锁定场景可接受频率，再选分辨率是更稳的路径。

### 3. 动态更新时要明确“何时生效”

涉及运行时调速/调光时，建议明确：

1. 当前周期立即生效，还是下周期生效。
2. 多通道是否要求同步更新。

把这条规则写清楚，后续排障会轻很多。

### 4. 命名体现语义而不是通道号

例如：

1. `pwm_led_backlight`
2. `pwm_motor_fan`
3. `pwm_buzzer`

而不是只叫 `tim3_ch1`。

语义命名能让代码、原理图和调试目标更容易对齐。

## 性能、稳定性、可维护性影响

1. 定时器/PWM 通常硬件开销低，但配置错误会直接影响系统时序稳定性和用户体验。
2. 没有统一更新策略时，动态调节场景容易出现间歇性毛刺和难复现故障。
3. 接口层把频率/占空比语义抽象好，后续做芯片迁移和驱动重构成本更低。
4. 把波形测量纳入常规验证，可以显著降低“代码看起来对、硬件表现不对”的排障成本。

## 面试 / 问答怎么讲

### 30 秒版本

定时器本质是硬件计数器，PWM 通常是定时器比较输出模式。频率由时钟和周期参数决定，占空比由比较值决定。真正难点在时钟链路、更新时机、引脚复用和波形验证。

### 3 分钟版本

可以从“时钟 -> 预分频 -> 计数 -> 比较 -> 输出”讲起，再给出 `f_pwm` 和 `duty` 的计算关系，说明为什么改 ARR 会影响分辨率。然后补充工程高频坑：pinmux、极性、预装载、运行时更新毛刺，以及示波器验证方法。

### 10 分钟版本

结合一个真实场景，比如风扇调速。先讲频率选型依据（噪声、驱动器要求、分辨率），再讲初始化链路和运行时调速策略（同步更新、限幅、斜坡），最后讲排障路径：先看引脚波形，再看时钟与寄存器，再看负载和电源完整性。

## 实战练习

1. 写一个 1kHz PWM 点灯程序，并把占空比从 10% 线性扫到 90%。
2. 在不改占空比百分比的前提下，把 PWM 从 1kHz 改到 20kHz，验证亮度或负载变化。
3. 对比开启和关闭预装载时，运行中修改 CCR 的波形差异。
4. 用输入捕获测另一路 PWM 的频率和占空比，形成“输出+测量”闭环。
5. 设计一个“呼吸灯”模块接口，要求业务层不直接接触寄存器。

## 关键要点

1. 定时器核心是时钟驱动计数，PWM 是比较输出机制。
2. 频率看时钟/预分频/周期，占空比看比较值比例。
3. 真正的工程坑通常在时钟链、更新时机、pinmux 和负载侧。
4. 先跑通最小波形闭环，再做多通道联动和高级功能扩展。
5. 示波器验证是定时器/PWM 排障的关键证据。
