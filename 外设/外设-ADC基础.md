# 外设-ADC基础

## 原始问题

ADC 到底是什么？为什么它看起来只是“把电压变成数字”，但一到真实项目里就会遇到采样不稳、读值抖动、量程不准、通道串扰、换算误差和时序冲突这些问题？真正做项目时，应该怎样系统掌握 ADC，而不是只会调用一次 `read()`？

## 先给结论

ADC 的本质是“在特定时刻对模拟电压做采样并量化为数字码值”，它不是“直接读到真实物理量”，而是“读到带采样条件和参考基准约束的离散结果”。

先记住下面几个结论：

1. ADC 结果是否可信，取决于参考电压、采样时间、输入源阻抗、噪声环境和校准状态。
2. ADC 输出是码值，不是电压本身；电压和物理量需要换算。
3. 采样频率、分辨率和噪声抑制通常是互相制约关系，不是越高越好。
4. 多通道扫描场景里，顺序、采样窗和触发时序经常决定最终稳定性。
5. 工程排障要走完整链路：传感器与前端电路 -> 参考电压 -> ADC 配置 -> 采样时序 -> 数据处理。

如果只能背“12 位 ADC 是 0~4095”，却讲不清为什么高源阻输入会失真、为什么采样时间太短会偏低、为什么同样传感器在不同板子上标定系数不同，就说明这部分还没有真正掌握。

## 这个知识解决什么问题

这篇笔记主要解决下面几类问题：

1. 刚接触 ADC 时，不清楚分辨率、参考电压、采样时间之间的关系。
2. 传感器读值明显不准或抖动很大，不知道先查硬件还是软件。
3. 多通道采样时出现串扰、延迟或错位，不知道根因在哪。
4. 面试时会背“ADC 采样”，但讲不清采样保持、量化误差和工程滤波思路。

它在 AI 时代仍然重要，因为 AI 可以生成 ADC 初始化和读取代码，但它不知道你的参考电压是否稳定、前端 RC 是否匹配、采样触发是否和 PWM 噪声重叠、温漂补偿是否做过。ADC 理解越扎实，越能判断 AI 代码是“能跑”，还是“数据不可用”。

## 核心概念 / 本质机制

### 1. ADC 在做哪三件事

ADC 核心流程可以拆成三步：

1. 采样（Sample）：在采样窗内获取输入电压。
2. 保持（Hold）：短时间保持该电压供内部比较。
3. 量化（Quantize）：映射为离散数字码值。

所以 ADC 结果总带有“采样时刻”和“量化精度”两个约束，不是连续真实信号本体。

### 2. 分辨率和码值范围

常见 ADC 分辨率有 8 位、10 位、12 位、16 位。

以 N 位 ADC 为例：

1. 码值范围通常是 `0 ~ (2^N - 1)`。
2. 最小量化步进约为 `Vref / (2^N - 1)`。

这意味着：

1. 分辨率越高，单步电压更小，理论上更细。
2. 但最终有效精度还受噪声、参考源和电路限制。

### 3. 参考电压为什么是 ADC 的“地基”

ADC 码值本质是相对参考电压 `Vref` 的比例。

常见换算：

1. `voltage = code * Vref / (2^N - 1)`。

所以：

1. `Vref` 漂移会直接造成测量漂移。
2. 同样 code 在不同参考电压下对应不同真实电压。
3. 高精度测量里，参考源稳定性往往比算法更关键。

### 4. 采样时间与输入源阻抗的关系

很多 ADC 前端有采样电容，采样窗太短时，电容来不及充到真实输入电压。

典型后果：

1. 高源阻信号读值偏低或不稳定。
2. 多通道切换时前后通道相互影响更明显。

工程上常见做法：

1. 提高采样时间。
2. 降低源阻抗（缓冲运放/优化分压）。
3. 对关键通道增加丢弃首样策略。

### 5. 单次采样、连续采样、扫描采样

常见 ADC 工作方式：

1. 单次采样：触发一次，转换一次。
2. 连续采样：持续转换同一通道。
3. 扫描采样：按通道序列依次转换。

工程取舍通常看：

1. 采样频率需求。
2. 通道数量。
3. CPU 预算（轮询/中断/DMA）。
4. 是否要求严格同步触发。

### 6. 触发源决定采样时序质量

ADC 可由软件触发，也可由定时器等硬件触发。

对稳定采样更常见的是硬件触发，因为它能保证固定节拍，减少软件调度抖动。

高频场景：

1. PWM 控制系统中，把 ADC 触发对齐到电流纹波较小的时刻。
2. 多通道同步采样中，用统一触发保证相位一致性。

### 7. 噪声、滤波与有效位数

ADC 读值抖动很常见，不等于 ADC 坏了。

常见处理思路：

1. 均值滤波（抑制随机噪声）。
2. 中值滤波（抑制毛刺）。
3. IIR 低通（平滑趋势）。
4. 过采样 + 抽取（换取更高有效分辨率）。

但滤波会引入延迟，控制系统里要平衡实时性。

## 数据流 / 控制流 / 时序关系

下面用“电位器电压采样”串最小主线：

```text
电位器输出模拟电压
-> ADC 输入通道与采样保持电路
-> 在触发时刻进行采样与量化
-> ADC 结果寄存器 / DMA 缓冲区得到码值
-> 软件换算电压或工程量
-> 上层逻辑用于显示、控制或告警
```

这条链上每一步都可能出问题：

1. 前端电路阻抗过高，采样不准。
2. 参考电压不稳，数据整体漂移。
3. 触发时序不稳定，采样抖动大。
4. 换算公式或标定系数错误，结果失真。
5. 滤波参数不合适，出现延迟或抖动残留。

## 最小可运行示例

下面给一个简化的寄存器级示例，目标：

1. 初始化单通道 ADC。
2. 读取码值并换算为毫伏。

```c
#define ADC_BASE            0x40012000
#define ADC_CR              (*(volatile unsigned int *)(ADC_BASE + 0x00))
#define ADC_SR              (*(volatile unsigned int *)(ADC_BASE + 0x04))
#define ADC_CHSEL           (*(volatile unsigned int *)(ADC_BASE + 0x08))
#define ADC_SMPR            (*(volatile unsigned int *)(ADC_BASE + 0x0C))
#define ADC_DR              (*(volatile unsigned int *)(ADC_BASE + 0x10))

#define ADC_CR_EN           (1U << 0)
#define ADC_CR_START        (1U << 2)
#define ADC_SR_EOC          (1U << 1)

#define ADC_RES_BITS        12U
#define ADC_MAX_CODE        ((1U << ADC_RES_BITS) - 1U)
#define ADC_VREF_MV         3300U
#define ADC_CHANNEL_IN3     3U

static void adc_init(void)
{
    ADC_CHSEL = ADC_CHANNEL_IN3;
    ADC_SMPR = 7U;             /* 示例：较长采样时间，降低高源阻误差风险 */
    ADC_CR |= ADC_CR_EN;
}

static unsigned int adc_read_code(void)
{
    ADC_CR |= ADC_CR_START;

    while (!(ADC_SR & ADC_SR_EOC))
        ;

    return (unsigned int)(ADC_DR & ADC_MAX_CODE);
}

static unsigned int adc_code_to_mv(unsigned int code)
{
    return code * ADC_VREF_MV / ADC_MAX_CODE;
}

int main(void)
{
    unsigned int code;
    unsigned int mv;

    adc_init();

    while (1) {
        code = adc_read_code();
        mv = adc_code_to_mv(code);

        (void)mv;
        for (volatile unsigned int i = 0; i < 50000; i++)
            ;
    }
}
```

这个示例里假设：

1. ADC 输入电压范围与参考电压范围匹配。
2. 通道 `IN3` 已正确连接到目标模拟信号。
3. 参考电压稳定且等于 3.3V。

如果你的板子参考电压是 2.5V、通道映射不同或 ADC 为差分模式，换算和配置都要改。

## 代码解读

### 1. 为什么先把链路跑成“可换算电压”

先完成 `code -> mV` 的最小闭环，能快速判断 ADC 基础链路是否打通。

这样后续接温度、压力、电流等物理量时，定位更清晰。

### 2. 为什么示例里采样时间选得较长

较长采样时间能降低高源阻场景的充电不足风险，先保证“读得稳”，再做性能优化更稳妥。

### 3. 为什么 `mv` 仍然不等于最终物理量

ADC 只给电压估计值，真实工程量还需要传感器特性换算和标定系数。

例如热敏电阻、霍尔电流传感器、压力传感器都各有转换关系。

### 4. 为什么这个示例不能直接量产

真实项目通常还要补：

1. ADC 校准流程。
2. 定时器触发与 DMA 采样。
3. 多通道扫描和缓存管理。
4. 滤波、去噪和异常值剔除。
5. 温漂补偿与工厂标定。

## 正确写法 vs 常见错误写法

| 场景 | 正确写法 | 常见错误写法 | 为什么错 |
| --- | --- | --- | --- |
| 电压换算 | 明确 Vref 和分辨率再换算 | 默认拿 3.3V 套所有板子 | 参考不同会整体偏差 |
| 采样时间 | 按源阻抗选采样窗 | 一律最短采样时间 | 高源阻场景易失真 |
| 触发方式 | 固定节拍优先硬件触发 | 随机软件触发 | 采样时序抖动大 |
| 多通道采样 | 评估通道切换与缓冲策略 | 直接扫描不验证串扰 | 数据相互污染 |
| 数据处理 | 结合滤波和标定 | 直接裸值上业务 | 抖动大且绝对值不准 |
| 排障手段 | 电路+波形+寄存器联查 | 只看上层打印 | 根因定位慢 |

## 边界条件与适用范围

1. 这篇笔记讲的是 MCU/SoC 常见片上 ADC 基础，不绑定特定厂商寄存器细节。
2. 不同芯片在输入结构、采样电容、参考源、校准机制、差分支持上差异很大。
3. 片上 ADC 适合中低速通用采样，高精度低噪声需求可能要外置高精度 ADC。
4. 采样精度不仅由 ADC 位数决定，还受模拟前端、PCB 布线、电源和地噪声影响。

## 常见坑与排查

| 现象 | 常见根因 | 优先验证方法 |
| --- | --- | --- |
| 读值明显偏低 | 采样时间太短；源阻过高 | 拉长采样时间、测输入阻抗 |
| 读值抖动大 | 参考不稳；电源噪声；地弹噪声 | 看参考源纹波、示波器测电源地 |
| 多通道互相影响 | 通道切换太快；前端驱动弱 | 插入等待/丢弃首样、加缓冲 |
| 满量程不到顶 | Vref 配置或量程理解错误 | 校验参考源和输入范围 |
| 全是 0 或全是满量程 | 通道接错；输入钳位；寄存器配置错 | 查原理图、测引脚电压、查配置 |
| 低速正常高速异常 | 采样链路带宽不够；DMA/中断丢数据 | 降采样验证、检查缓冲区 |
| 温度变化后偏差增大 | 未做温漂补偿或标定 | 做多温点标定对比 |

### 推荐排查顺序

1. 先看原理图和输入范围，确认信号是否在 ADC 可测范围内。
2. 再查参考电压与供电稳定性。
3. 再查通道、采样时间、触发方式和转换配置。
4. 再抓数据看码值分布与噪声特征。
5. 最后再调整滤波、标定和上层换算策略。

### 常用验证方式

1. 用稳压源给 ADC 输入固定电压，看读值线性。
2. 用万用表/示波器同步测输入电压与 ADC 结果。
3. 采集一段原始码值做均值、方差和频谱观察。
4. 分别在空载、负载、不同温度下对比漂移。
5. 用已知标准点做两点或多点标定验证。

## 工程落地建议

### 1. 区分“原始采样层”和“工程量层”

建议分层：

1. ADC 驱动层只负责稳定采样与输出码值。
2. 转换层负责 `code -> voltage -> physical`。
3. 业务层只消费工程量，不直接碰寄存器。

这样后续替换 ADC 芯片或调整标定策略更容易。

### 2. 先保证测量可重复，再追求极限精度

工程里先看同条件重复性是否稳定，再看绝对误差。

重复性都不稳时，先查噪声、触发和前端，不要急着堆复杂算法。

### 3. 用定时器触发统一采样节拍

做控制类系统时，尽量让 ADC 采样与控制循环用同一时基。

这样能减少相位漂移和时序抖动导致的控制噪声。

### 4. 把标定当必选项而不是可选项

涉及精度指标的场景，建议把标定流程纳入交付：

1. 标定点数量。
2. 标定温度范围。
3. 系数存储与版本管理。

## 性能、稳定性、可维护性影响

1. ADC 配置和前端设计直接决定数据可信度，错误会把上层算法全部带偏。
2. 触发和缓冲策略不稳时，系统会出现间歇性数据异常，排障成本很高。
3. 分层设计（采样/换算/业务）能显著降低后续维护和移植成本。
4. 把标定、噪声评估和回归采样纳入流程，能提升量产一致性。

## 面试 / 问答怎么讲

### 30 秒版本

ADC 是把模拟电压在采样时刻量化为数字码值的外设。码值要结合参考电压和分辨率换算，工程难点在参考稳定性、采样时间与源阻抗匹配、触发时序和滤波标定。

### 3 分钟版本

可以先讲 ADC 三步：采样、保持、量化，再讲 `code` 与 `Vref` 的换算关系。然后补工程高频坑：采样时间太短导致高源阻失真、参考波动导致整体漂移、多通道切换导致串扰。最后给出排障主线：电路 -> 参考 -> 配置 -> 时序 -> 数据处理。

### 10 分钟版本

结合一个真实传感器案例展开：先定义精度目标和采样率，再选触发策略（定时器触发+DMA），说明采样时间与前端设计取舍，再讲滤波与标定流程，最后通过实测数据闭环验证（线性、重复性、温漂）。

## 实战练习

1. 采集电位器电压，完成 `code -> mV` 换算并串口输出。
2. 对同一输入分别测试短采样时间和长采样时间，比较稳定性差异。
3. 做一个 4 通道扫描采样，并统计每通道均值和方差。
4. 用定时器触发 + DMA 采样，和软件轮询方式对比抖动。
5. 对一个温度传感器做两点标定，验证标定前后误差变化。

## 关键要点

1. ADC 读到的是离散码值，必须结合参考和分辨率解释。
2. 采样时间、源阻抗、参考稳定性是数据可信度核心。
3. 多通道和高频采样场景里，触发时序和缓冲策略决定稳定性。
4. 先建立最小可验证链路，再做滤波、标定和工程化扩展。
5. 排障必须联动看模拟前端、数字配置和数据统计，不只看一层。
