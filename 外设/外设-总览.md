# 外设-总览

## 原始问题

为什么要单独建立一个 `外设` 目录，后续哪些知识应该放到这里，哪些又更适合继续放在 `Linux`、`硬件` 之类的目录里？

## 先给结论

`外设` 目录用于集中存放“面向外设本身”的知识，而不是把所有和外设沾边的内容都混在一起。

优先放到这里的内容通常包括：

1. GPIO、UART、I2C、SPI、CAN、USB、PWM、ADC、DAC、RTC、Watchdog、Timer 这类外设本身的原理和用法。
2. 外设初始化流程、寄存器主线、时序关系、最小闭环示例。
3. 外设常见问题、调试方法、工程落地方式和面试表达。
4. 同一类外设在 MCU、SoC、裸机、RTOS 或 Linux 下都能迁移复用的共性知识。

不优先放到这里的内容通常包括：

1. 重点在 Linux 设备树、platform 总线、`gpiod`、`pinctrl`、driver model 的内容，优先放 `Linux`。
2. 重点在电平、上下拉、时钟、复位、寄存器映射等更底层硬件本质的内容，优先放 `硬件`。
3. 重点在 C / C++ 语法、内存、对象模型、工具链的内容，优先放 `C_C++`。

## 这个目录解决什么问题

单独建立 `外设` 目录，主要是为了解决这几个问题：

1. 避免 GPIO、UART、I2C、SPI 这类高频主题散落在 `Linux` 和 `硬件` 目录里，不利于复习和横向对比。
2. 让“外设知识”形成稳定主题，不再每次都临时找地方放。
3. 以后扩展新外设时，可以直接沿用同一套命名和组织方式。
4. 面试、项目排障、板级 bring-up 时，可以更快定位到同类外设笔记。

## 存放边界

可以先按下面这个判断规则来放：

1. 如果主题核心是“这个外设是什么、怎么工作、怎么初始化、怎么调试”，优先放 `外设`。
2. 如果主题核心是“Linux 怎么描述、匹配、申请、驱动这个外设”，优先放 `Linux`。
3. 如果主题核心是“这个外设背后的硬件本质和电气约束”，优先放 `硬件`。

例如：

1. `外设-GPIO基础`
2. `外设-UART基础`
3. `外设-I2C通信基础`
4. `外设-SPI时序与模式`
5. `外设-ADC采样基础`

而像下面这些，更适合继续放原目录：

1. `Linux-pinctrl与GPIO`
2. `Linux-I2C设备树绑定`
3. `硬件-GPIO与电平`

## 后续可扩展主题

后续这个目录可以继续沉淀这些稳定主题：

1. `外设-GPIO基础`
2. `外设-UART基础`
3. `外设-I2C通信基础`
4. `外设-SPI通信基础`
5. `外设-CAN基础`
6. `外设-PWM基础`
7. `外设-ADC基础`
8. `外设-DAC基础`
9. `外设-RTC基础`
10. `外设-Watchdog基础`

## 关键要点

1. `外设` 目录用于沉淀“面向外设主题本身”的知识。
2. 目录划分优先看主题主线，不是看是否偶然提到了外设。
3. 同一主题如果明显更偏 Linux 框架或硬件本质，应继续放到对应目录，不强行塞进 `外设`。
