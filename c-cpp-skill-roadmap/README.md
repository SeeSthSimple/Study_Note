# C/C++ Skill Roadmap

这个目录用于长期记录和强化我的 C/C++ 编程能力，目标不是零散学语法，而是持续建立：

- 扎实的语言基础
- 可靠的工程实现能力
- 清晰的调试与排错能力
- 可迁移的代码设计能力
- 从题目、模块到项目的完整落地能力

## 核心要求

1. 高知识密度
   每个主题都应尽量覆盖概念、本质机制、边界条件、常见误区、示例代码、调试方法，而不是只做表面总结。

2. 高实践性
   每个知识点都应尽量配套可运行代码、改造练习、实际工程场景或面试/项目式题目，避免只看不写。

3. 高可扩展性
   内容应能逐步从基础语法扩展到 STL、现代 C++、内存模型、并发、编译链接、设计模式、性能优化、工程架构与项目实战。

4. 高规划性
   学习内容应有阶段划分、优先级、里程碑和复盘机制，形成从“理解”到“实现”再到“优化”的成长闭环。

5. 高工程相关性
   强调真实开发中的代码组织、接口设计、错误处理、日志、测试、构建、调试、性能与可维护性，而不是停留在教材式知识点。

6. 高迁移能力
   每个主题尽量总结“这个知识在什么场景下有用”“如何迁移到项目中”“如何判断该不用它”，提升举一反三能力。

7. 高可验证性
   学到的结论应尽量通过代码、编译结果、运行结果、单元测试、边界输入或调试过程进行验证，而不是只凭印象记忆。

8. 高复盘价值
   每次学习尽量沉淀“我原来错在哪里、现在理解了什么、以后如何更快定位问题”，把经验转化为稳定能力。

## 内容标准

后续在这个目录中沉淀的内容，默认尽量遵循下面的输出标准：

- 先讲本质，再讲语法，再讲使用场景。
- 先给最小可运行示例，再扩展到更完整版本。
- 每个重要主题尽量包含“正确写法 vs 常见错误写法”。
- 不只讲“怎么写”，还要讲“为什么这样写”和“不这样写会怎样”。
- 不只讲通过编译，还要讲未定义行为、资源泄漏、悬垂引用、越界、竞态、ABI、异常安全、性能退化等风险。
- 尽量从 C 与 C++ 两个维度对比：哪些思想共通，哪些习惯必须区分。
- 尽量包含调试方法：如何复现、如何定位、如何验证修复有效。

## 建议训练路线

后续内容优先可沿着下面的路线逐步推进：

1. C 基础强化
   指针、数组、函数指针、结构体、内存布局、预处理、模块化、编译链接、错误处理。

2. C++ 核心强化
   引用、类与对象、构造析构、拷贝控制、继承、多态、模板、RAII、异常、安全资源管理。

3. 现代 C++ 强化
   智能指针、移动语义、完美转发、lambda、`auto`、范围 for、`constexpr`、泛型设计、标准库容器与算法。

4. 工程能力强化
   构建系统、日志、测试、断言、调试器、性能分析、代码组织、接口抽象、库设计、跨模块协作。

5. 项目能力强化
   从小型练习逐步进入模块开发、组件封装、并发处理、网络/文件/嵌入式相关项目、重构与优化。

## 目录约定

- `notes/`
  记录知识点、专题笔记、机制分析与对比总结。

- `exercises/`
  记录小练习、算法实现、语法强化题、边界测试题。

- `projects/`
  记录完整一点的项目型训练、模块封装、重构实践或综合案例。

- `templates/`
  存放可复用代码骨架，如错误处理模板、类设计模板、模块接口模板、Make/CMake 示例等。

- `reviews/`
  记录复盘、错题、易错点、编码风格改进、性能与设计反思。

## 执行原则

- 学习一个主题时，尽量同时产出：原理说明 + 示例代码 + 常见坑 + 调试方法 + 可延伸练习。
- 如果一个主题不能写出代码，说明理解还不够。
- 如果代码只能跑通简单输入，说明工程能力还不够。
- 如果不知道为什么这样设计，说明抽象能力还不够。
- 如果修完 bug 不能总结成规则，说明复盘深度还不够。
