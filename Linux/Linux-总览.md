# Linux-总览

## 原始问题

`Linux` 目录在这套嵌入式知识库里主要承接什么内容？哪些问题该放这里，哪些又更适合放到 `驱动开发`、`外设` 或 `硬件`？

## 先给结论

`Linux` 目录主要承接嵌入式 Linux 平台的系统基础、设备树、用户态与内核态理解、系统排障和平台行为，不直接等同于“所有驱动代码都放这里”。

优先放到这里的内容通常包括：

1. Linux 核心基础、文件、权限、进程、日志、系统服务。
2. 设备树、pinctrl、时钟、复位、电源域等平台描述层知识。
3. 用户态到内核态的交互、系统启动后的观测与排障。
4. 更偏平台框架理解的主题，而不是单一驱动子系统实现细节。

更适合放到其他目录的内容包括：

1. 单一外设本身的原理和最小闭环，优先放 `外设`。
2. 更偏驱动模型、总线匹配、probe、资源管理的内容，优先放 `驱动开发`。
3. 更偏硬件本质和电气行为的内容，优先放 `硬件`。

## 这个目录解决什么问题

1. 板子能启动，但设备树、日志、资源状态和系统行为串不起来。
2. 学驱动时只盯代码，却缺少平台层上下文。
3. 工作中经常要结合 `dmesg`、`/proc`、`/sys`、设备树和系统状态来定位问题。

## 关键要点

1. `Linux` 目录承接的是嵌入式 Linux 平台理解，不是所有主题的兜底目录。
2. 如果主题重点在系统行为、平台描述和系统排障，优先放这里。
3. 如果主题重点已经进入驱动模型细节，应继续细分到 `驱动开发`。
